# 39. 楽曲と効果音

2026-09-23 のユーザー指示で、BGM と効果音を作り直した。
指示は「今の音楽はゲームのイメージに合っていない。参照せずに新しく作る。曲はシーンとステージで切り替える。効果音はもっと迫力があってよい」である。
36 章の「BGM・効果音も新しいドットテーマの世界観に合わせて再制作する」を、この章で実施した。
以下の数値は初期値であり、人が遊んで調整する（TBD-29）。

## 39.1 方向

画面は、黒地に緑の燐光で描く端末と、星の出た夜の戦場である。
それまでの 8 曲は明るいチップチューンで、この画面の緊張感と合っていなかった。
新しい曲は、暗めのレトロシンセで作る。
アナログ風のベースとパッド、パルス波のアルペジオ、機械的なノイズの打楽器を共通の音色とし、短調か教会旋法で書く。

全曲で同じ動機を使う。
主音、下の属音、主音、短 3 度、2 度、下の短 7 度、主音の 7 音で、リズムは 16 分音符で 2・2・4・3・1・2・2 とする。
ステージごとに調、テンポ、音色を変え、同じ動機が別の場所で鳴るように聞かせる。
リザルトだけは動機を長調に置き換えて音価を倍にする。

## 39.2 曲の割り当て

曲の枠と切り替えの仕組みは変えていない。
`apps/client/src/app/musicTracks.ts` の 8 枠の中身だけを差し替えた。

| 枠 | 流す画面 | 調と旋法 | BPM | 小節 | 長さ | 性格 |
|---|---|---|---|---|---|---|

| lobby | 部屋の一覧 | C 自然短音階 | 100 | 16 | 38.4 秒 | 探信音が回り、入れる部屋を探す |
| room | 部屋の中 | G 自然短音階 | 112 | 16 | 34.3 秒 | 16 分のベースが秒読みのように刻み、開始を待つ |

| stone-bridge | 石橋 | E フリジアン | 105 | 20 | 45.7 秒 | 太鼓と金属音。半音上の F に触れる重い刻み |

各曲は 4 小節単位の部で構成し、刻みだけの部、動機の部、属和音で張る部、打楽器を抜く谷の部を持つ。
部の切り替わりはクラッシュ、フィル、スイープで示す。

## 39.3 制作と再現

曲は `tools/music` の合成器で書き出す。
外部の音源や録音は使わない。

```sh
pnpm music:render                      # 8 曲を書き出し、loops.json と provenance.json を更新する
pnpm music:render --only ridgeline     # 1 曲だけ
node tools/music/analyze.mjs ridgeline # 層ごとの音量と帯域の偏りを見る
```

- 記譜は `tools/music/tracks/*.mjs` に文字で書く。1 step は 16 分音符で、`"D4/2 A3/2 D4/4"` のように「音名/step 数」を並べる。
- 層の音量は倍率ではなく、その層だけを鳴らしたときの積分ラウドネス（LUFS）で指定する。楽器の出力の大小に左右されず、曲をまたいで釣り合いを保てる。
- ノイズは種つきの乱数で作る。同じ記譜と種からは同じ波形が出る。
- 書き出した OGG を手で編集しない。記譜を直して書き出し直す。`provenance.json` の SHA-256 と一致しないとテストが落ちる。
- ffmpeg や libvorbis の版が違うと、同じ記譜からでも OGG のバイト列は変わる可能性がある。書き出し直したら、OGG と `provenance.json` と `loops.json` を同じコミットに入れる。
- 旧曲は `assets/workbench/audio/chiptune-2026-09-14` に移して保存した（36 章の「既存音源は制作記録として保存する」）。

## 39.4 ループと音量の契約

- 1 小節が整数サンプルになる BPM だけを使う（44.1 kHz で 240 × 44100 / BPM が整数）。ループの終わりを丸めずに済み、`loops.json` の `end` はサンプル数を 44100 で割った値になる。
- 曲は円環として書き出す。ループの終わりをはみ出した音の尾は先頭へ足し、残響や遅延のような状態を持つ効果はループを 2 周通して 2 周目だけを使う。継ぎ目で残響が途切れず、段差も出ない。
- 継ぎ目の段差は、曲の中で普通に起きる隣り合うサンプルの差の範囲に収める。e2e では上位 0.1% の差を超えないことを確かめる。
- 仕上げの音量は積分ラウドネス -13.5 LUFS、サンプルピークの天井は -3 dBFS とする。Vorbis の符号化とサンプル間のピークで 1.5 dB ほど上振れするため、書き出し後のトゥルーピークが旧曲と同じ -1.4 dBTP 以下に収まる値にした。旧曲は -12.4〜-14.3 LUFS だったので、保存済みの BGM 音量の感じ方は変わらない。
- 30 Hz 以下は仕上げで落とす。聞こえない低域に音量の余裕を食われないためである。

| 曲 | 積分ラウドネス | トゥルーピーク |
|---|---|---|
| hangar | -13.6 LUFS | -1.4 dBTP |
| lobby | -13.6 LUFS | -2.6 dBTP |
| room | -13.7 LUFS | -1.9 dBTP |
| ridgeline | -13.6 LUFS | -2.1 dBTP |
| stone-bridge | -13.7 LUFS | -1.9 dBTP |
| terraces | -13.7 LUFS | -1.8 dBTP |
| sky-islands | -13.6 LUFS | -2.4 dBTP |
| result | -13.5 LUFS | -1.4 dBTP |

## 39.5 効果音

効果音は従来どおり、その場で合成する。
音の名前（`SoundName`）、`playSound(name)`、鳴らす時刻は変えていない。
1 つの音を 1 本のオシレーターの掃引で作っていたのをやめ、`apps/client/src/app/soundRecipes.ts` に書いた複数の層の重ね合わせで作る。

- 発射は、破裂の立ち上がり（高域のノイズを数十 ms）、胴の低音（正弦波の音程を急に落とす）、爆風（低域通過のノイズ）を重ねる。
- 着弾は、30 Hz 前後まで落ちるサブの低音、破裂、cutoff を下げながら沈むノイズの余韻、破片のノイズを重ねる。
- 全体に tanh の歪みを通して倍音を足し、短い残響へ送る。
- 大きい着弾の瞬間だけ BGM を下げ、約 0.1 秒置いてから 0.35 秒の時定数で戻す（`duck`）。BGM の音量設定は変えずに、効果音を前へ出す。
  下げている 0.12 秒のあいだに浅い値の音が届いても、深いほうを保つ。自機に当たった砲弾では爆発（0.5）の直後に被弾（0.3）が鳴り、後の値で上書きすると外れたときより下がり方が浅くなるためである。
- 同じ音が 30 ms より詰めて届いたら重ねない。同じ瞬間の多段着弾で音量が跳ねるのを防ぐ。履帯の音は従来どおり 75 ms に 1 回とする。
- 鳴らすたびに音程を数 % 揺らす。同じ音の連打を機械的に聞かせないためである。
- 効果音をまとめる圧縮器は、閾値 -14 dB、比 4、knee 8 dB、attack 3 ms、release 250 ms とした。サブの低音が入って、旧設定（閾値 -12 dB、比 8、release 100 ms）では後ろの音がうねったためである。

武器ごとの性格は次のとおりである。
多段の武器は 1 回を短く軽くし、7 回や 9 回続いても濁らないようにする。

| 武器 | 発射 | 着弾 |
|---|---|---|
| 標準砲 | 破裂、胴の低音、爆風。基準 | 1.2 秒の余韻とサブの低音。基準 |
| トリプル弾 | 55 ms おきの 3 連の破裂 | 標準砲より短い中くらいの爆発 |
| マルチ弾 | 70 ms おきの 3 連の乾いた破裂 | 0.1 秒の爆竹。9 回続く前提 |
| 貫通弾 | 胴の低音と、うなるモーター | 削るような歪んだのこぎり波と中域のノイズ |
| レーザー弾 | 下へ滑るのこぎり波の光線音 | 0.1 秒の焼ける音。7 回続く前提 |
| 掘削弾 | 鈍い射出と導火線の擦過音 | 最も低く長い地響き（1.6 秒、26 Hz まで） |
| 浮遊弾 | 上へ浮く正弦波と風切り | 柔らかい破裂と広い爆風 |
| 針弾 | 高域の鋭い擦過 | 短く硬い刺突音 |

被弾（`hit`）は金属の鳴りと鈍い衝撃で下がる向きの音、命中の手応え（`hitConfirm`）は上がる向きの音にする。
向きの違いで区別する方針は、単一の音だった版から引き継いだ。
決着（`finish`）は 2 段の爆発と、落ちていく電源音で作る。

同じ出力経路（圧縮器、効果音量 50%）で書き出した、旧音との比較を次に置く。
値は 100 ms 窓の RMS の最大値と、-50 dB を下回るまでの長さである。
BGM は音量 50% で約 -19.5 LUFS になるので、旧音の多くは BGM より下に埋もれていた。

| 音 | 旧 RMS | 新 RMS | 旧の長さ | 新の長さ |
|---|---|---|---|---|
| 標準砲の発射（`fire`） | -36.0 dB | -18.6 dB | 0.09 秒 | 0.90 秒 |
| 標準砲の着弾（`explosion`） | -24.0 dB | -15.8 dB | 0.36 秒 | 1.23 秒 |
| 掘削弾の着弾 | -24.5 dB | -14.4 dB | 0.44 秒 | 1.45 秒 |
| 決着（`finish`） | -22.3 dB | -13.2 dB | 0.65 秒 | 1.54 秒 |
| 被弾（`hit`） | -27.1 dB | -21.0 dB | 0.22 秒 | 0.57 秒 |
| 命中の手応え | -38.6 dB | -24.7 dB | 0.07 秒 | 0.41 秒 |
| レーザー弾の着弾 | -36.7 dB | -28.3 dB | 0.13 秒 | 0.10 秒 |
| 秒読み（`tick`） | -44.5 dB | -41.3 dB | 0.04 秒 | 0.05 秒 |
| 履帯（`move`） | -53.6 dB | -51.5 dB | 0.03 秒 | 0.03 秒 |

新しい音のサンプルピークは最大 -8.1 dBFS（トリプル弾の発射）で、効果音量 100% でも -2 dBFS に収まる。
秒読みと履帯は繰り返し鳴るので、旧音から 2〜3 dB だけ上げるに留めた。

手触りのうち数値で固定できるものは `apps/client/test/soundRecipes.test.ts` で固定する。
多段の着弾が 0.15 秒以内であること、大きい爆発が 0.7 秒以上続き 35 Hz 以下まで落ちて BGM を 4 割以上下げること、被弾が下がり命中が上がる向きであることを確かめる。
数値を変えるときはこのテストと本章の表を更新する。

## 39.6 検証と未確認のこと

- 楽曲の書き出し、音階、ループ長、継ぎ目、ラウドネス、ハッシュは `tools/music/music.test.mjs` で確かめる。記譜の音が宣言した音階から外れたら落ちるので、音名の打ち間違いが残らない。借用音は各曲の `allow` に書く。
- シーンごとの切り替え、継ぎ目、音量設定は `apps/e2e/world-tests/audio.spec.ts` で確かめる。
- 曲と効果音の良し悪しは、スペクトログラムと数値でしか確かめていない。制作者は音を聴いていない。印象、音量の釣り合い、長く聞いたときの疲れは人が遊んで判断する（TBD-29）。
- 配布用ビルドの音声 e2e（`apps/e2e/production-tests/audio.spec.ts`）は Chromium、Firefox、WebKit で通った。古い Safari には `decodeAudioData` で Ogg Vorbis を読めない版があるが、実機では確かめていない。BGM を OGG だけで配る作りは旧曲から変えていない。
