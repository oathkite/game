# 26. WebSocket移動同期の確認画面

2026-09-10。工程B/Cへの接続試作。ブランチ`codex/2d-multiplayer-rules`。

## 起動

このブランチのworktreeで、次の2プロセスを起動する。

```sh
pnpm --filter @game/server exec tsx src/lab/main.ts
pnpm --filter @game/client dev --host 127.0.0.1 --port 5185
```

`http://127.0.0.1:5185/?prototype=network`を複数タブで開く。
WebSocketはloopbackの8794、許可Originはlocalhost/127.0.0.1の5185のみ。
既存の5184のカメラ試作・通常のv1ゲームサーバーとは別に動かす。

## 操作と実装

- 固定8席・2チームの実験マップ。接続ごとにサーバーが未割当PlayerIdを付与する。
- 手番の参加者だけ左右へ1歩ずつ操作でき、20秒で次の手番へ進む。
- 確定した位置を最大10Hzで全接続へ配信する。操作のACKは本人だけへ即時に返す。
- 相手側は125msの受信bufferで補間する。古いeventSeqは捨て、更新停止時は外挿しない。
  落下などの不連続は即反映する。本人の表示は確定位置で、入力予測はまだ導入していない。
- ランダムUUIDの復帰tokenをsessionStorageに保持し、切断から60秒以内の再読み込みで同じ席に戻る。
  接続中のtokenで別socketから乗っ取ることはできない。再読み込みで未確定入力を自動再送しない。
- join前の移動、他席の移動、不正schema、過大payload、過剰messageを拒否する。
- session割当・復帰管理を配信処理から分離し、既存コードへの分岐追加をDEV入口だけに抑えた。

サーバーを再起動するとtokenは失効する。「新しい接続で参加」で取り直す。
期限切れの切断席は再戦時に解放する。試合途中には別人へ割り当てない。

## 検証

- 実WebSocket8本で、1人の移動を全接続が受信することを確認。
- 非手番からの入力拒否、切断→token復帰→同じcommand再送で二重移動しないことを確認。
- Playwrightで独立2ブラウザcontextを使用。相手画面の座標更新、操作禁止、reload後の同じ席・位置、移動再開を確認。
- 補間・古いframeの排除・外挿停止・落下の単体テスト。
- workspace 463テスト、全パッケージtypecheck、client production buildを実行。

## 射撃・結果・復帰期限の追加

- 確定moveSeqを伴う射撃をサーバーだけで処理。クライアント座標の追加、旧手番、他席、変更された同一commandIdを拒否。
- サーバーの再生期限で手番を進め、クライアントのACKを待たない。勝敗・12roundまたは20分の引き分け・降参・再戦を接続。
- 固定loadoutのcannon/diggerは1弾道・1着弾。射撃前の確定位置から弾を動かし、着弾時に地形を更新、最後の300msで機体を落下位置へ補間する。
  飛行時間を表示期限へ収める試験用timelineであり、全武器の正式impact tick契約は未実装。
- 復帰frameのserverTimeから再生位置を復元する。端末時刻を手番判定には使わない。厳密な往復時刻同期は後続。
- 60秒の復帰期限を過ぎた切断は脱落。同時に期限が切れた人は一括で脱落させ、全滅を誤って片側の勝利にしない。
