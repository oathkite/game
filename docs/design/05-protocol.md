# 5. 通信プロトコル

この章では、クライアントとサーバーの間で交換するメッセージと、サーバーが権威を持つ範囲を定める。
通信はターン制なので WebSocket 1 本で足り、フレーム単位の同期は行わない。
メッセージの型は共有パッケージに Zod スキーマとして定義し、サーバーは受信したすべてのメッセージを検証する。

## 5.1 サーバー権威の範囲

サーバーが決めるもの、クライアントが決めるものを分ける。

サーバーが決める。

- 部屋の状態と手番
- 風の値
- 制限時間の起点と期限
- 射撃確定の受理か拒否
- 弾道の結果（着弾点、削れた地形、ダメージ、落下、勝敗）

クライアントが決める。

- 移動の途中経過、向き、仰角（射撃確定時にまとめて送る）
- パワー値（押していた時間から換算した結果だけを送る）
- 弾道の描画（サーバーと同じ関数で再計算する）

弾道の結果をサーバーが決めているのに、クライアントが再計算するのは矛盾ではない。
サーバーは計算の入力（向き、仰角、パワー、風、位置、地形）を確定し、その入力から一意に導ける結果をクライアントが描く。
同じ入力から同じ結果が出ることは [データモデル](./06-data-model.md) の決定論の契約で保証する。
サーバーは着弾点と結果も送るので、クライアントは再計算の結果と照合し、食い違ったらサーバーの値で上書きして不整合を記録する。

## 5.2 メッセージ一覧

方向は C→S がクライアントからサーバー、S→C がサーバーからクライアントである。
すべてのメッセージは `type` を持ち、以下では `type` の値をメッセージ名として使う。

### ロビー

| 名前 | 方向 | 内容 |
|---|---|---|
| `lobby.subscribe` | C→S | 変化通知の配信を開始する |
| `lobby.query` | C→S | 検索語、状態の絞り込み、マップ、ページ番号 |
| `lobby.page` | S→C | 該当する部屋の 1 ページ（表示名、マップ、人数、観戦者数、状態）、総件数、ページ番号 |
| `lobby.changed` | S→C | 一覧に変化があった。クライアントは表示中の条件で `lobby.query` を送り直す。数秒に 1 回まで間引く |
| `lobby.unsubscribe` | C→S | 配信を止める |

### 部屋

| 名前 | 方向 | 内容 |
|---|---|---|
| `room.create` | C→S | 匿名 ID、名前、主色と副色、表示名、公開か非公開か、マップ名 |
| `room.join` | C→S | 部屋コード、匿名 ID、名前、主色と副色 |
| `room.spectate` | C→S | 部屋コード、匿名 ID、名前。観戦者として入る |
| `room.takeSeat` | C→S | 観戦者が空いた席に参加者として移る。主色と副色 |
| `room.joined` | S→C | 部屋コード、招待用の URL、自分の席番号、接続トークン、部屋の状態（[データモデル](./06-data-model.md) の RoomState） |
| `room.state` | S→C | 部屋の状態の全体。入退室、ready、色や名前の変更、マップ変更のたびに配信する |
| `room.ready` | C→S | ready の on か off |
| `room.profile` | C→S | 名前、主色、副色の変更 |
| `room.setMap` | C→S | オーナーのみ。マップ名 |
| `room.kick` | C→S | オーナーのみ。対象の席番号 |
| `room.start` | C→S | オーナーのみ |
| `room.leave` | C→S | 退出 |
| `room.dissolve` | C→S | オーナーのみ。解散 |
| `room.closed` | S→C | 部屋が消えた理由（解散、放置） |
| `room.error` | S→C | 理由（部屋がない、満室、対戦中、権限がない、開始条件を満たさない、など） |

部屋の中の変化は差分ではなく `room.state` の全体で配信する。
参加者は最大でも数人で、状態は小さいので、差分の適用ミスを避ける方を優先する。

### 対戦の開始

| 名前 | 方向 | 内容 |
|---|---|---|
| `match.setup` | S→C | マップ名、両者のスポーン x と主色と副色、HP、先攻の席番号、ターン上限。`room.start` が受理されたときに配信する。観戦者が途中で入った場合は `conn.state` で代える |
| `match.ready` | C→S | マップの読み込みが終わった |

### ターン

| 名前 | 方向 | 内容 |
|---|---|---|
| `turn.start` | S→C | ターン番号、手番の席番号、風の値、突風フラグ、期限（サーバー時刻） |
| `turn.fire` | C→S | 向き、仰角、パワー、移動後の x |
| `turn.result` | S→C | 下記 5.3 の結果 |
| `turn.replayDone` | C→S | 再生が終わった |
| `turn.pass` | S→C | ターン番号、理由（時間切れ、無効な射撃） |

### 対戦の終了と切断

| 名前 | 方向 | 内容 |
|---|---|---|
| `match.surrender` | C→S | なし |
| `match.finished` | S→C | 勝者の席番号か引き分け、理由（HP、リングアウト、ターン上限、降参、切断）、各席の与えたダメージと直撃数、経過ターン数 |
| `result.close` | C→S | リザルトを閉じた。全員が閉じるか一定時間で部屋は募集中に戻る |
| `conn.opponentDisconnected` | S→C | 再接続を待つ期限 |
| `conn.opponentReconnected` | S→C | なし |
| `conn.resume` | C→S | 接続トークン |
| `conn.state` | S→C | 現在の対戦状態のすべて（[データモデル](./06-data-model.md) の MatchState） |

## 5.3 `turn.result` の内容

射撃結果は、クライアントが再計算するための入力と、照合するための結果の両方を持つ。

入力側。

- ターン番号
- 撃った席番号
- 向き、仰角、パワー
- 移動後の x（サーバーが検証済みの値）
- 風の値（`turn.start` と同じ値。再接続後の再生のために重複して持つ）

結果側。

- 着弾点（x、y）。マップ外に消えた場合は null
- 削れた地形の円（爆心と半径）。消えた場合は null
- 両者のダメージと着弾後の HP
- 両者の落下後の位置。落下していなければ着弾前と同じ
- リングアウトした席番号の一覧
- 決着していれば `match.finished` と同じ内容

入力側だけあれば結果は再計算できるが、結果側も送る理由は二つある。
一つは、再計算が食い違ったときにサーバーの値で上書きするためである。
もう一つは、再接続したクライアントが再生を飛ばして確定状態に直行できるようにするためである。

## 5.4 `turn.fire` の検証

サーバーは `turn.fire` を受け取ると、[ターン状態遷移](./04-turn-state-machine.md) の 4.3 に定めた順で検査する。
Zod スキーマによる型と範囲の検査（向きが左か右、仰角が 10 から 90、パワーが 0 から 100 の整数）を最初に行い、その後に手番と状態、移動の検査を行う。
失敗した場合は `turn.pass` を理由付きで返し、Resolving に進む。

同じターンに `turn.fire` が 2 回届いた場合、最初の 1 回だけを受理し、2 回目は無視する。

## 5.5 部屋の操作の検証

主色と副色は [グラフィックの方向性](./08-visual-direction.md) の候補にある値だけを受け付ける。
入室時に先にいる参加者と主色が重なっていても入室は許し、`room.state` で衝突を示す。
衝突している参加者の `room.ready` は拒否する。
自動で別の色に振り替えることはしない。
振り替えると、選んだ色と違う戦車で対戦が始まるためである。

`room.start` は、送信者がオーナーで、人数が上限に達し、オーナー以外が全員 ready で、色の衝突がないときだけ受理する。
`room.setMap`、`room.kick`、`room.dissolve` は送信者がオーナーでなければ拒否する。
`room.profile` は対戦中（部屋が InMatch）には拒否する。
`room.join` は部屋が InMatch か満室なら拒否する。
`room.spectate` は観戦者が上限に達していれば拒否する。
`room.takeSeat` は部屋が Open で席が空いているときだけ受理する。
観戦者からの `turn.fire`、`room.ready`、`match.surrender` は拒否する。

## 5.6 時刻の扱い

制限時間の期限は、サーバーの時刻で `turn.start` に含める。
クライアントは接続時にサーバー時刻との差を測り、期限を自分の時計に変換して表示する。
差の測定は、接続直後に往復時間を数回測って中央値を取る。
表示のずれは 1 秒以内に収まればよく、判定はサーバーだけが行う。

## 5.7 接続トークン

部屋に入った時点でサーバーが発行し、再接続のときに `conn.resume` で送る。
トークンは部屋の寿命と同じで、部屋が閉じれば無効になる。
匿名 ID は端末を識別するだけで席を証明しないので、席の証明はこのトークンで行う。
