# 5. 通信プロトコル

この章では、クライアントとサーバーの間で交換するメッセージと、サーバーが権威を持つ範囲を定める。
通信はターン制なので WebSocket 1 本で足り、フレーム単位の同期は行わない。
メッセージの型は共有パッケージに Zod スキーマとして定義し、サーバーは受信したすべてのメッセージを検証する。

## 5.1 サーバー権威の範囲

サーバーが決めるもの、クライアントが決めるものを分ける。

サーバーが決める。

- 部屋の状態と手番
- 風の値
- 制限時間の起点と期限
- 射撃確定の受理か拒否
- 弾道の結果（着弾点、削れた地形、ダメージ、落下、勝敗）

クライアントが決める。

- 移動の途中経過、向き、仰角（射撃確定時にまとめて送る）
- パワー値（押していた時間から換算した結果だけを送る）
- 弾道の描画（サーバーと同じ関数で再計算する）

弾道の結果をサーバーが決めているのに、クライアントが再計算するのは矛盾ではない。
サーバーは計算の入力（向き、仰角、パワー、風、位置、地形）を確定し、その入力から一意に導ける結果をクライアントが描く。
同じ入力から同じ結果が出ることは [データモデル](./06-data-model.md) の決定論の契約で保証する。
サーバーは着弾点と結果も送るので、クライアントは再計算の結果と照合し、食い違ったらサーバーの値で上書きして不整合を記録する。

## 5.2 メッセージ一覧

方向は C→S がクライアントからサーバー、S→C がサーバーからクライアントである。
すべてのメッセージは `type` を持ち、以下では `type` の値をメッセージ名として使う。

### 部屋

| 名前 | 方向 | 内容 |
|---|---|---|
| `room.create` | C→S | ニックネーム、色、マップ名 |
| `room.join` | C→S | 部屋コード、ニックネーム、色 |
| `room.created` | S→C | 部屋コード、招待用の URL、自分の席番号、接続トークン |
| `room.joined` | S→C | 席番号、接続トークン、相手のニックネームと色 |
| `room.opponentJoined` | S→C | 相手のニックネームと色 |
| `room.error` | S→C | 理由（部屋がない、満室、色が相手と同じ、など） |

### 対戦の開始

| 名前 | 方向 | 内容 |
|---|---|---|
| `match.setup` | S→C | マップ名、両者のスポーン x と色、HP、先攻の席番号、ターン上限 |
| `match.ready` | C→S | マップの読み込みが終わった |

### ターン

| 名前 | 方向 | 内容 |
|---|---|---|
| `turn.start` | S→C | ターン番号、手番の席番号、風の値、突風フラグ、期限（サーバー時刻） |
| `turn.fire` | C→S | 向き、仰角、パワー、移動後の x |
| `turn.result` | S→C | 下記 5.3 の結果 |
| `turn.replayDone` | C→S | 再生が終わった |
| `turn.pass` | S→C | ターン番号、理由（時間切れ、無効な射撃） |

### 対戦の終了と切断

| 名前 | 方向 | 内容 |
|---|---|---|
| `match.surrender` | C→S | なし |
| `match.finished` | S→C | 勝者の席番号か引き分け、理由（HP、リングアウト、ターン上限、降参、切断） |
| `conn.opponentDisconnected` | S→C | 再接続を待つ期限 |
| `conn.opponentReconnected` | S→C | なし |
| `conn.resume` | C→S | 接続トークン |
| `conn.state` | S→C | 現在の対戦状態のすべて（[データモデル](./06-data-model.md) の MatchState） |

## 5.3 `turn.result` の内容

射撃結果は、クライアントが再計算するための入力と、照合するための結果の両方を持つ。

入力側。

- ターン番号
- 撃った席番号
- 向き、仰角、パワー
- 移動後の x（サーバーが検証済みの値）
- 風の値（`turn.start` と同じ値。再接続後の再生のために重複して持つ）

結果側。

- 着弾点（x、y）。マップ外に消えた場合は null
- 削れた地形の円（爆心と半径）。消えた場合は null
- 両者のダメージと着弾後の HP
- 両者の落下後の位置。落下していなければ着弾前と同じ
- リングアウトした席番号の一覧
- 決着していれば `match.finished` と同じ内容

入力側だけあれば結果は再計算できるが、結果側も送る理由は二つある。
一つは、再計算が食い違ったときにサーバーの値で上書きするためである。
もう一つは、再接続したクライアントが再生を飛ばして確定状態に直行できるようにするためである。

## 5.4 `turn.fire` の検証

サーバーは `turn.fire` を受け取ると、[ターン状態遷移](./04-turn-state-machine.md) の 4.3 に定めた順で検査する。
Zod スキーマによる型と範囲の検査（向きが左か右、仰角が 10 から 90、パワーが 0 から 100 の整数）を最初に行い、その後に手番と状態、移動の検査を行う。
失敗した場合は `turn.pass` を理由付きで返し、Resolving に進む。

同じターンに `turn.fire` が 2 回届いた場合、最初の 1 回だけを受理し、2 回目は無視する。

## 5.5 色の検証

`room.create` と `room.join` の色は、[グラフィックの方向性](./08-visual-direction.md) の候補にある値だけを受け付ける。
`room.join` の色が先に入室した側と同じ場合は `room.error` を返し、入室させない。
自動で別の色に振り替えることはしない。
振り替えると、選んだ色と違う戦車で対戦が始まるためである。

## 5.6 時刻の扱い

制限時間の期限は、サーバーの時刻で `turn.start` に含める。
クライアントは接続時にサーバー時刻との差を測り、期限を自分の時計に変換して表示する。
差の測定は、接続直後に往復時間を数回測って中央値を取る。
表示のずれは 1 秒以内に収まればよく、判定はサーバーだけが行う。

## 5.7 接続トークン

部屋に入った時点でサーバーが発行し、再接続のときに `conn.resume` で送る。
トークンは部屋の寿命と同じで、部屋が閉じれば無効になる。
アカウントを持たないので、このトークンが席を証明する唯一の手段になる。
