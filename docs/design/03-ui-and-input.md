# 3. 画面と操作

この章では、横持ち前提の画面レイアウト、PC とモバイルで共通にする入力の扱い、パワーゲージの挙動を定める。
操作の設計で守るのは、「パワーの長押しを離すタイミング」の体験を PC とモバイルで同じにすることである。

## 3.1 画面の向きと大きさ

- 横持ちを前提とする。縦持ちのときは横に回すよう促す画面を出す。
- 描画領域はマップ全体（1600 × 900）を基準にし、端末の画面に合わせて縦横比を保ってスケールする。
- 描画領域の左右に余白ができる端末では、その余白にコントローラー UI を置く。余白がない端末では、コントローラー UI をマップ上に半透明で重ねる。

マップ全体を常に表示する。
ポトリスにはズームとスクロールがあったが、両者の位置と風を一目で見られることを優先する。
自機周辺の拡大表示は、遊んでみて必要なら足す（TBD-5）。

## 3.2 レイアウト

画面を左右のコントローラー領域と中央のマップ領域に分ける。

```
+--------+--------------------------------+--------+
| 左パネル|            マップ領域             | 右パネル|
|        |  上部: 風、ターン、残り時間        |        |
| 角度    |                                | パワー   |
| 移動    |                                | 射撃    |
+--------+--------------------------------+--------+
```

- 上部中央：風の向きと強さ、手番と残りターン、残り時間、両者の HP。
- 左パネル：角度の調整、左右の移動、残り歩数。
- 右パネル：パワーゲージと射撃ボタン。

右利きの親指で射撃を押す前提で、射撃を右に置く。
左右の入れ替えは設定で選べるようにする。

## 3.3 入力の統一

マウスとタッチを別々に扱わない。
すべての入力を Pointer Events（pointerdown、pointermove、pointerup、pointercancel）で受け、マウスかタッチかは見ない。
これにより、長押しの開始と終了はどの端末でも同じイベントで検出できる。

タッチ端末での誤動作を防ぐため、次を行う。

- ゲーム画面全体に `touch-action: none` を指定し、長押しやドラッグがスクロールやズームに解釈されないようにする。
- 長押し中のコンテキストメニューを抑止する。
- pointercancel（着信や画面回転などで入力が中断された場合）は、長押しの中断として扱い、射撃を確定しない。

物理キーボードがある端末では、補助としてキー操作も受け付ける。

| 操作 | キー |
|---|---|
| 角度 | 上下矢印 |
| 移動 | 左右矢印 |
| パワー | スペース（押している間だけ伸びる） |

## 3.4 角度の調整

角度は 0 度から 180 度の整数で、左パネルの上下ボタンかキーで 1 度ずつ変える。
ボタンを押し続けると連続で変わる。
90 度を越えると左向きの射撃になるので、左右の切り替え操作は別に持たない。
現在の角度は数値で表示し、機体からは角度の向きを示す短い線を出す。
表示上は「左 30 度」のように向きと仰角に分けて読めるようにする。

弾道の予測線は表示しない。
表示すると風を読む必要がなくなり、うまいショットの報いが消えるためである。
前のターンに自分が撃った弾道の軌跡は、次の自分のターンまで薄く残す。
これが唯一の「読むための手がかり」になる。

## 3.5 パワーゲージ

パワーは押している時間で決まる。
押し始めから離すまでの時間をクライアントが計測し、パワー値に変換して送る。
サーバーはパワー値の範囲だけを検査し、押していた時間そのものは受け取らない。
押下と解放を別々にサーバーへ送ると、回線の揺れがパワーに乗るためである。

ゲージの伸び方は時間基準で定義し、フレームレートに依存させない。
描画が 30 fps でも 120 fps でも、同じ時間押せば同じパワーになる。

| 項目 | 初期値 |
|---|---|
| 0 から 100 に達する時間 | 1.5 秒 |
| 100 に達した後の挙動 | 100 で止まり、押し続けても変わらない |

100 で止める方式を選んだのは、往復や巻き戻しにすると「最大パワーを出したい」場面で失敗が運になるためである。
一方で、止める方式だと「押し続ければ最大」が保証され、最大付近の緊張がなくなる。
この点は遊んで確認し、必要なら往復方式に変える（TBD-6）。

ゲージの表示は、押している間だけ右パネルに大きく伸びる。
離した瞬間に確定値を一瞬固定表示し、弾の発射演出に移る。

## 3.6 移動

左パネルの左右ボタンを押している間、1 歩ずつ移動する。
残り歩数を数値で表示し、0 になったらボタンを無効にする。
勾配の制限で進めない場合は、機体がその場で止まり、ボタンに進めない表示を出す。

移動は 1 歩ごとにクライアントで判定して即座に表示し、サーバーには射撃確定時に移動後の位置だけを送る。
判定の詳細は [マップ仕様](./02-map.md) で定める。

## 3.7 残り時間の表示

ターンの残り時間は上部に秒単位で表示する。
残り 5 秒からは色を変えて警告する。
残り時間はサーバーの通知を基準にクライアントで減らし、サーバーの時刻を正とする。

## 3.8 結果の再生

サーバーから射撃結果が届いたら、両クライアントは同じ物理コードで弾道を再計算して描く。
着弾で爆発の演出を出し、地形マスクを更新し、ダメージと落下を描く。
再生中は両者とも操作できない。

再生時間はおよそ 4 秒を見込み、一戦の長さの計算に含めている。
弾の滞空時間が長い高角度ショットでは、これより長くなる。
再生を早送りする操作は最初の版では持たない。

## 3.9 ロビーと部屋

対戦前の画面は最小にする。

1. トップ：「部屋を作る」と「部屋に入る」の 2 つ。
2. 部屋を作る：部屋コードと招待リンクが表示され、相手の入室を待つ。
3. 部屋に入る：部屋コードを入力するか、招待リンクを開く。
4. 両者が揃ったら、マップを表示して対戦を開始する。

ランダムマッチングは持たない。
遊ぶ人がいない状態で待たせるより、知り合いを招待して確実に遊べる形を先に作る。
アカウントも持たず、ニックネームだけを入力する。
