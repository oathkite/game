# 22. 最大8人・自由なチーム編成とリアルタイム移動

2026-09-09 / 設計提案。相手の移動をリアルタイム表示することは追加のユーザー要件。
仕様全体は[20章](20-global-game-redesign.md)、通信基盤は[23章](23-global-architecture.md)。

## 22.1 人数と所属

参加者総数をN、空でないチーム数をTとし、`2 <= N <= 8`、`2 <= T <= N`を満たすすべての編成を許可する。
各人はちょうど1チームに所属し、1チームの最大人数はN-1。チームはA〜Hで識別する。
1対1〜4対4、1:1:1:2、2:2:2、1:2、1:7、8人FFAを同じデータモデルで扱う。
チーム名や色を比較して敵味方を判断せず、不変のTeamIdで判定する。

カスタム部屋は非対称編成を許し、「1人 対 2人・人数差あり」を開始前に全員へ明示する。
全員同数に揃える自動補正や、人数の少ないチームへのHP補正は初期版では行わない。
自由編成は対応範囲であり、すべてが競技的に公平という意味ではない。
クイック参加は人数の揃った1対1・2対2を入口にし、カスタム編成と同じ待ち列へ混ぜない。

機体の塗装色は重複可能。既存7色から8人を選べるよう、主色重複によるready禁止を廃止する。
識別にはチーム文字・形の印・プレイヤー番号を使い、色は補助にする。味方判定を塗装に結び付けない。

## 22.2 準備・開始・参加変更

オーナーを含む全参加者がreadyを持つ。開始条件は、2人以上、2チーム以上、全員接続済み・ready、全員配置済み、マップが編成に対応すること。
部屋の定員が8でも、2人で条件を満たせば開始できる。定員を埋めることは必須にしない。

マップ・ruleSet・チーム移動・参加者入退室・武器構成変更で全員readyを解除する。
外見だけの変更、観戦者入退室では解除しない。readyはroomRevisionに対して行い、古いrevisionの開始要求を拒否する。
開始時に参加者、所属、順序、loadout、MapSpec、ruleSetVersionを固定する。
対戦途中の加入・チーム移動・補充・復活は初期版では行わない。再接続は同じPlayerIdの復帰に限る。

オーナー退出時は最古の接続中参加者へ権限を渡す。対戦中のオーナーに他人の追放や全体解散権限を与えない。
退出は本人の降参として処理する。結果後は部屋へ戻り、残った参加者で編成を組み直す。

## 22.3 手番順と人数差

推奨は「生存プレイヤー1人につき1roundに1行動」。チームごとに1行動とはしない。
チーム交互方式だけにすると1対2で単独側が各相手の2倍行動し、実質的な補正になるためである。

初回にseed付きでチーム順とチーム内順を抽選し、各チームから1人ずつ取り出して初期ringを作る。
例：A={A1,A2}、B={B1,B2}なら A1,B1,A2,B2。
A={A1}、B={B1,B2}なら A1,B1,B2。
A={A1}、B={B1}、C={C1}、D={D1,D2}なら A1,B1,C1,D1,D2。
8人FFAは各チーム1人なので、抽選した8人の順番になる。

各roundはそのringを順に一周し、脱落済みをskipする。round境界で再抽選・先頭回転はしない。
手番順を途中で回すと、前round最後のプレイヤーが次round最初にも行動するなどの連続手番を作るためである。
人数差で同じチームが続く箇所は許容し、順番を事前表示する。再戦ではseedを変えて先手を抽選し直す。
脱落者の枠を別の味方へ渡さず、生存人数が減ったチームは行動機会も減る。

初期値は操作20秒、TurnFocus 0.6秒、通常再生3〜6秒、再生上限8秒。
8人なら自分の次の手番まで最大付近で `7 × (20 + 0.6 + 8) = 200.2秒` 待つ可能性がある。
この待ち時間は重大なリスク。早く撃てば短くなるが、解消したとは扱わない。
自分の次手番表示、他人の移動と弾の観察、武器説明の閲覧を提供し、alphaで測定する。
待ち時間が受け入れられなければ操作15秒案を比較する。同時手番化は別ルールとして再設計する。

## 22.4 射撃・ダメージ・決着

移動・角度・長押しpower・8武器・風・破壊地形の基礎は維持する。
1手番に射撃1回、移動予算30cellを初期値とする。味方を含む全機体への爆風・地形落下を計算する。
friendly fireは初期ON。OFFでも地形を消して味方を落とせるため、曖昧な保護を作らない。
味方への与ダメージは結果で別集計し、通常の与ダメージに加算しない。
機体同士の押し出しは導入せず、移動中の相互衝突はなし。近接しても全対象のダメージを計算する。
弾が複数機へ同時接触した場合は同じsimulation tickで処理し、安定したPlayerId順で結果を並べる。

HP<=0またはring outで個人が脱落。脱落者は操作不能、以後の当たり判定から除外する。
残骸は短時間の表示だけとし、遮蔽物としては残さない。操縦者の身体損傷は描写しない。
初期版は機体内で落胆→fadeを推奨し、最終アニメーションはアートレビューで確定する。

勝利は全着弾と落下を解決した後に生存チーム数で判定する。
1チームならそのチームの勝ち、0チームなら引き分け、2以上なら継続。
自爆と敵全滅、複数弾、貫通の途中で暫定勝者を通知しない。
個人降参・再接続猶予切れはその人だけ脱落とし、味方が生きていれば続行する。
チーム全体の降参投票は初期版では追加しない。

試合の初期上限は12roundまたは開始から20分。上限到達時は進行中の射撃解決まで完了して引き分けにする。
人数差があるため総HPで勝者を選ばない。途中HPによる順位も付けず、勝利チームと各人の成績を表示する。
20分の上限でacting中ならその手番deadlineまで受け付け、次の手番は始めない。最大超過は1手番とその再生。
自動結果閉じは60秒を初期値とし、全員が戻る選択をすれば先に部屋へ戻る。

## 22.5 相手の移動のリアルタイム表示

射撃前の移動を、本人以外の参加者・観戦者にも表示する。カメラ自体は各クライアント独立。
既存の「発射時に最終xだけ送信・検証」は廃止し、移動開始からサーバーが経路・予算・地形を判定する。
位置だけを自由に送れる方式や、client時刻で移動量を増やせる方式にはしない。

推奨プロトコルは、有限個の歩行コマンドをまとめて送る方式。
`move.command`はmatchId、turnId、commandId、moveSeq、direction、steps（1〜2）を持つ。
押下中に最大10Hzで送る。サーバーは受信時刻のtoken budgetで最大10cell/秒、1手番30cellに制限する。
初期のburst creditは2cellまで。経過時間とともにcreditを補給するが、ためても2cellまで。
手番開始時にcreditと移動seqを初期化する。受信遅延で移動を瞬間的に30cell消費させない。
各stepを既存の段差・落下規則で検証し、成功したstepだけ予算を消費する。壁への入力で残量を減らさない。
途中の致死落下はその場で脱落として処理する。射撃を待たず、同じ決着規則を適用する。

有効なseqは受理・部分成功・拒否のいずれでも処理結果を記録し、同じseqを再実行しない。seqが飛んだ場合はsnapshot同期を要求する。
拒否された入力を本人の予測queueから除き、サーバーの位置へ戻して残りだけ再適用する。

サーバーは確定位置x/y・facing・残量・ackMoveSeq・serverTime・eventSeqを10Hz以下で配信する。
本人は同じ移動関数で予測し、ack以降の未確定コマンドを再適用して補正する。
相手は100〜150msの補間bufferを持ち、受信した確定点を滑らかに繋ぐ。長時間外挿はせず、更新が途絶えたら止める。
瞬間移動を隠すために地形の中を横切る補間はしない。落下などの不連続は別eventで再生する。

通信遅延は消せない。「リアルタイム」は移動中に継続更新する意味で、完全同時ではない。
250ms RTTで、相手の描画遅延p95を350ms以内にすることを初期目標とする。異地域で超える場合は実測値を表示する。
移動している機体が画面外なら、ミニマップと方向マーカーが動く。自分のManualカメラを奪って追いかけない。

移動は逐次確定するため、時間切れ・切断・発射取消でも既に確定した位置には留まる。
時間切れは射撃なしでpass。切断は後述の猶予に入り、未受理の移動を復帰時に自動再送しない。
この意味は従来の発射時一括確定からのルール変更として、操作案内にも反映する。

`turn.fire`には最後に確認したmoveSeqを含める。同一WebSocket上で先行移動を処理した後、サーバーの確定位置から射撃する。
seq不足・不整合ならfireを拒否し、位置と理由を返す。clientのx/yは射撃原点に採用しない。
移動中にpower chargeを開始したら、clientは移動入力を止める。サーバーはfire受理後のmoveを拒否する。
同じcommandIdのfire再送には同じ結果を返し、二発目を発生させない。

角度とpowerは本人のローカル情報とし、発射時に公開する。移動方向は公開される。
相手の砲身は最後に公開された角度または中立角で描き、現在照準を推測したanimationをしない。

## 22.6 時刻・再接続・再生

サーバーがturnId、startsAt、deadlineAtを決める。カメラ導入はstartsAt前の600msの枠内で実行する。
移動と射撃はstartsAt以降、deadlineAt以前にサーバーが受理したものだけ有効。
締切延長にclient時刻を信頼しない。UIは時刻同期してカウントダウンし、遅延で未受理なら明確に表示する。
旧1秒graceを暗黙に残さず、v2では受理期限を一つにする。

切断しても全体を止めない。本人は60秒以内に同じsessionで復帰可能、手番deadlineは継続する。
切断中に来た手番も最大20秒でpass。猶予切れで脱落する。短い切断で即チーム敗北にはしない。
全員切断してもalarmで猶予を処理し、結果を保存する。再接続が古い手番を復活させない。

再生はサーバー指定のreplayStartsAt / replayEndsAtを使う。通常の画面演出とは独立した期限。
長い弾道は表示時間への写像を短縮できるが、物理stepや着弾順は変えない。
replay完了ACKを全員から集めて次へ進む方式は廃止し、遅い1人や観戦者が試合を止めないようにする。
追いつけないclientは確定stateへ同期してから次手番を表示する。表示完了を待って自分だけ時間を延ばさない。
結果が早く届いても最終着弾の表示までは演出を完了し、確定済み入力は遮断する。

途中参加の観戦者は最新snapshotを受け取る。初期上限は1部屋8観戦者とし、規模拡大はfan-out検証後。
観戦者にも未確定の角度・power・将来の乱数seedは渡さない。復帰tokenは観戦tokenと権限を分ける。

## 22.7 マップとデータの契約

MapSpecはid、version、width、height、地形生成定義、spawn候補、対応人数・編成条件を持つ。
配布済みid/versionを上書きせず、terrain digestで全員の初期地形を照合する。
対戦中にマップの幅・高さは変更しない。破壊するのは占有maskであり、表示倍率ではない。

spawnはseed付きで決定し、重複・即落下・初手の強制自爆・移動不能を検査する。
対称編成は鏡像配置、非対称・FFAは人数別の検証済み候補配置を用いる。人数だけで等間隔に並べない。
チーム別配置と射程の両立を確認できないマップは、その編成で選択不可にする。
全編成を遊べる汎用マップを最低1枚用意し、特定編成をサポートする専用マップを増やす。
既存8マップは一度に拡大せず、互換版と新人数対応版を区別する。

幅を400→500へ増やすだけでも、射程、最大simulation steps、固定小数点の積の上限、地形メモリ、spawn間距離を再検証する。
全員が全員へ即射撃できる必要はないが、移動しても攻撃圏へ入れない孤立配置は不可。
0風の主砲に加え、最大逆風と全8武器の到達性を測り、拡張後に武器倍率を決める。

| モデル | 主な変更 |
|---|---|
| Player | 不変PlayerId、TeamId、seatIndex、hp、position、connected、eliminatedAt |
| Team | TeamId、表示印、memberIds。生存状態はPlayerから導出 |
| Match | playersの可変配列、teams、turnRing、round、turnId、currentPlayerId、MapSpec参照 |
| ShotResult | PlayerIdごとのdamage/hp/position、順序付きimpacts。team勝利はengineで判定 |
| Result | winnerTeamIdまたはdraw、reason、全員のstats、match/version識別子 |
| Room | maxPlayers、members、team assignment、roomRevision、ruleSet、準備状態 |

配列のindexを本人識別に使わない。退室した場所に別人が入っても過去のeventが新しい人へ適用されないようにする。

## 22.8 受け入れテスト

2〜8人の整数分割は合計65通り。そのうち単一チーム7通りを除く58通りすべてを生成して開始・手番・決着を試験する。
同じ人数構成でもPlayerIdやTeamIdの並べ替え、seed、先手を変えて不変条件を検査する。

- 1人1チーム、1対7、2対2対2、1対1対1対2、4対4を代表E2Eとする。
- 1roundで生存者が1回ずつ行動。途中脱落はskip、味方の枠追加なし、チーム変更なし。
- 同時全滅、複数弾で両陣営全滅、味方だけに被弾、最後の1人の降参、リングアウトで正しい結果。
- 移動の過剰steps、予算超過、duplicate、逆順seq、旧turnId、なりすまし、壁・坂・致死落下。
- 移動中fire、移動中切断、未ACKから復帰、締切直前、0/100/250/500ms RTTで最終位置一致。
- 8クライアントが移動を観察でき、遅い観戦者や再生ACK欠落が次手番を止めない。
- 旧1対1goldenは物理の回帰用に維持し、手番や時間切れなど意図的変更はv2の別期待値で検査。
