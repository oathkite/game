# 8. グラフィックの方向性

> 2026-09-09 再設計提案：本章の旧仕様から変更する範囲は[20章](20-global-game-redesign.md)の対応表を参照。カメラ・多人数・リアルタイム移動・世界公開の新しい実装目標は20〜23章を優先する。実装済みを意味しない。

> 2026-09-26: 新デザインの制作基準（16章）と、搭乗者やアバターを扱う11〜19章は削除した。理由は[0章](00-world-and-experience.md)にある。

[世界観](./00-world-and-experience.md)を配色、文字、画面、スプライトへ落とし込む。
本章は今後制作する画面の仕様であり、現在の黒地に緑文字の UI から置き換える目標である。
動作試験台と baseline-v2 の素材は実装済み。ゲーム本体の画面への導入は未実装である。

## 8.1 ドットと表示サイズ

> 2026-09-27：ドットの格子、パレット、スプライトの描き方は [40 章](40-pixel-art-refresh.md)を優先する。本節の 12 art px/cell の素材パックは、画像素材を取り下げた 36 章の時点で使われなくなった。

地形と物理は **セル**、スプライトの原画は **art px**、画面上の寸法は **CSS px** で扱う。
三つを同じ単位に固定しない。
マップは 400 × 225 セルのまま維持する。

マシン、武器、VFX は共通のドット密度で制作する。
画像は nearest-neighbor で表示し、ぼかしや滑らかな陰影を焼き込まない。
UI の文字とボタンは物理セルの倍率から独立させる。

ガレージのプレビューは整数倍率を基本とする。
対戦ではマップの縦横比を保ち、使える領域に合わせて倍率を決める。
全マップ表示を維持し、操作盤の寸法は実寸で検証する（TBD-21）。
従来の左右 144 px パネルを新 UI の必須寸法にはしない。

新パックは共通192×160 art px、12 art px/cellで制作する。試験台のPC・モバイル表示を検証し、ゲーム内の最小対戦倍率は引き続きTBD-9で確認する。

## 8.2 色の役割

UI の配色とプレイヤーの色は別に管理する。
UI は深い青、明るい中立色、操作用のサフランイエローを基調とし、警告に暖色を使う。
以下は制作開始時の仮値であり、実画面で確認して確定する（TBD-22）。

| UI の役割 | 仮の色 | 使用箇所 |
|---|---|---|
| 背景 | #101C2C | 外周と HUD の下地 |
| 暗いパネル | #1B3044 | 操作盤と補助パネル |
| 主文 | #F6F1DF | 暗い面の文字 |
| 補助文 | #B9C9D3 | 状態説明 |
| 明るいパネル | #F6F1DF | ガレージの選択面 |
| 明るい面の文字 | #182B3A | 設定項目と説明 |
| 選択と主要操作 | #FFC345 | 選択の輪郭と主要ボタン |
| 注意 | #F1C46A | 残り時間の警告と未完了の準備 |
| 危険 | #F18B7B | 接続エラー、離脱、低 HP の補助表示 |

サフランイエローや暖色の塗りボタンには暗い文字を使う。
選択には輪郭とチェック、準備には文字、エラーには理由を添える。
無効状態も読める濃さを保ち、なぜ押せないかを近くに表示する。
配色だけで操作状態を区別しない。

主色と副色は現在の 10 色（protocol の `PLAYER_COLORS`）の識別子を維持する。
画面では副色を「カラー 1」、主色を「カラー 2」と呼ぶ。機体の上の部品（砲塔と砲身）の色から順に並べる（[43 章](./43-tank-skins.md)）。
red、orange、yellow、cyan、blue、pink、purple の実値は protocol の COLOR_HEX を参照する。
UI の仮 palette でこれらの値を書き換えない。
部屋の主色の衝突ルールも維持する（TBD-10）。

| プレイヤー側の色 | 使用箇所 |
|---|---|
| 主色 | 車体（足回りのフレーム）の塗装面、名前の印、弾と VFX の識別部分 |
| 副色 | 砲塔、砲身、アンテナの先 |
| 固定色 | 金属、履帯、輪郭 |

砲塔と足回りの形はプレイヤーがスキンとして選ぶ（[43 章](./43-tank-skins.md)）。当たり判定と砲口の位置は形によらず変えない。
主色と副色が同じでも、固定色と明暗で部品の境界が分かるようにする。

## 8.3 文字と部品

ドット文字は短いタイトル、見出し、装飾的な数値へ限定する。
説明、入力欄、部屋名、通信状態には読みやすい日本語の sans-serif を使う。
既存の DotGothic16 は短い見出しの候補とし、新フォントは配布条件と実寸を確認して決める（TBD-23）。

| 用途 | 初期の寸法方針 |
|---|---|
| 本文と入力 | 16 CSS px を基準 |
| 補助ラベル | 14 CSS px を基準。重要情報を小さくして収めない |
| 短いドット見出し | 使用フォントに合う整数倍率 |
| 残り時間と角度 | 等幅の数字。桁数で位置を動かさない |
| タッチ対象 | 高さと押下範囲は 44 CSS px 以上 |

パネルは単純な角丸の面とし、細い枠を画面全体へ重ねない。
押せるものは輪郭と余白で示し、押下時に浅く沈む反応を返す。
選択済みと hover を別にし、キーボードのフォーカスにも輪郭を付ける。

## 8.4 対戦前後の画面

ガレージではマシンを大きく見せる。
背景の整備道具は低彩度に抑え、輪郭を隠さない。
デスクトップは左にプレビュー、右に選択内容を置く。
縦画面はプレビュー、項目、主要操作の順にし、主要操作をスクロール領域から分ける。
プレビューは画面を圧迫しない高さとし、従来の下限 240 px を必須にしない。

通常画面は「マシンの色」と「砲塔と足回りのスキン」を要約し、モーダルで選ぶ（[43.8](./43-tank-skins.md#438-出撃準備のカスタマイズ)）。
候補が一つしか実装されていない項目は、選択できるように見せず現在の素材を表示する。
比較時は角度、倍率、姿勢、背景を揃える。

ロビーは部屋名、マップの形、人数、観戦者数、状態、入室操作を読みやすく並べる。
部屋は両者のマシンを対にし、名前、武器、準備状態を同じ位置に揃える。
主色の衝突や開始できない理由は文字で示す。

リザルトは勝敗と決着理由を先に伝え、両者の成績を置く。
「部屋に戻る」と「ロビーへ」を明示し、未実装のランクや報酬枠を並べない。
演出が結果を読む時間や再戦操作を妨げないようにする。

## 8.5 対戦画面と風

対戦画面はフィールド、上部の状態表示、下部の操作盤で構成する方針とする。
上部は両者の名前、HP、中央に手番と残り時間を置く。
下部は左に移動と角度、右に武器と射撃をまとめ、左右入れ替えを維持する。
帯の高さと狭い横画面への配置は TBD-21 で検証する。

マシンには小さい識別印を添え、HUD の名前の印と主色を揃える。
機体の名前と HP を機体の上へ密集させない。

風は風のメーターに矢印と数値で表し、突風の通知は出さない。
2026-09-27 のユーザー指示で、数値を出さない方針から改めた（理由は 1.5）。
メーターは背景装飾とは分離する。
背景の旗や煙を別の風の計器として動かさない。
風の粒（40.7）は残すが、強さを読むための計器はメーターとする。

| 風のメーター | 初期値 |
|---|---|
| 位置 | 下部の操作盤の中で、角度メーターの真下。操作盤の配置は下の「操作盤の 2 段」に書く |
| 出す画面 | CPU 戦、自由練習、オンライン対戦。オンラインの観戦中（脱落した後を含む）は、操作盤の代わりの帯の右端に出す。ターゲットチャレンジには出さず、操作盤もこれまでの 1 段のままにする。06 面のヒントが葉で風を読ませるので、出すかは TBD-43 で決める |
| 出す時期 | 常に出す。CPU 戦と自由練習は、1 ターン目の風が決まるまで（開始時のマップ紹介の間）数値を「—」にして矢印を描かない。それまでの風の値 0 は未定の意味で、無風と見せないためである。メーターを消さないのは、1 ターン目で操作盤の段組みが動かないようにするためである。オンラインは対戦の開始時にサーバーが風を引くので、紹介の間も値を出す |
| 形 | 中央に風の絶対値、左右に 10 目盛りずつの軌道。風の吹く側へ、中央から風 1 につき 1 目盛り伸びる矢印を描く。無風は数値 0 と目盛りだけ |
| 寸法 | 片側 20 × 7 art px。風 1 が 2 art px。1 art px = 2 CSS px（40.3）で描き、全体の幅は 104 CSS px。広い画面（幅 1200 以上、高さ 700 以上のタッチ以外）は武器のアイコン（40.10）と同じく 1 art px = 3 CSS px にして、幅 152 CSS px。数値は 16 px、広い画面は 20 px |
| 目盛り | 風 1 ごと。5 と 10 を長くする。矢印の先端は、風の値の目盛りに重なる |
| 色 | 矢印と数値は緑（`#33ff66`）、目盛りは濃い緑（`#0f4d24`）、5 と 10 は中の緑（`#1fb04a`）。操作盤の黒の地にそのまま置く |
| 範囲外の値 | 受け取った値をそのまま数値に出し、矢印は 10 で止める |
| 読み上げ | 「右向きの風 6」「左向きの風 3」「無風」、風が決まる前は「風は未定」。風が変わると、画面に出ない読み上げ用の文（`aria-live="polite"`）で知らせる |

風を出す操作盤は 2 段にする。
上の段は、自分で動かす角度メーターとパワー。
下の段は、角度メーターの真下に風のメーター、パワーの真下に残り移動のバーを並べ、状況を読む帯にする。
武器は 2 段にまたがる。
操作盤の高さ（広い画面 160 px、標準 120 px、狭い画面 96 px、タッチ 112 px）は変えない。
練習の戦場の大きさを操作盤の高さから計算していて（`CameraPrototype.tsx` の `hudBottom`）、オンラインの戦場も操作盤の行の高さに従うので、高さを変えると戦場が狭まるためである。

| 配置 | 上の段 | 下の段 |
|---|---|---|
| 広い画面 | 角度メーター 144 → 114 px、パワー 100 px | 風のメーター 21 px、残り移動。段の間 8 px |
| 標準 | 角度メーター 108 → 86 px、パワー 80 px | 風のメーター 16 px、残り移動。段の間 6 px |
| 狭い画面 | 角度メーター 84 → 68 px、パワー 68 px。角度の列を 84 → 104 px に広げる | 風のメーター 16 px、残り移動。段の間 4 px |
| タッチ | 角度メーター 72 px のまま、パワー 80 → 76 px。十字キーと発射は変えない | 風のメーター 16 px、残り移動。段の間 4 px |

残り移動のバーは、パワーの左端に揃える。
タッチの縦持ち（幅 480 px 未満）だけは角度の列（72 px）にメーター（104 px）が収まらない。
角度の列を広げるとパワーの列が 360 px 幅で 36 px まで細るので、メーターを下の段でパワーの列へ 32 px はみ出させ、残り移動をその分だけ右から始める。
幅 480 px 以上のタッチ（横持ち、タブレット）は、角度の列を 104 px に広げてメーターを収める。

動きを減らす設定では風の粒を消す（`pixelWind.ts`）ので、メーターを置く前はこの設定で風を読む手段が無かった。
メーターは動かないので、この設定でも出す。
見せ方の調整は TBD-43 で行う。

置き場所は 2026-09-27 の同じ日に 3 回変えた。
はじめは残り時間の真下に置き、次にユーザー指示で角度メーターの近くへ移したが、角度メーターの下には入らないので操作盤の上端の外（戦場の上）に置いた。
戦場の低い横画面では左下の機体を隠したので、さらにユーザー指示で、操作盤の中に収まるよう、操作盤を上に書いた 2 段に組み直した。
狙いを付けるときに見る角度メーターの真下に置くことは、風の計器を操作盤の読みやすい場所に置くという当初の方針にも沿う。

以下の小窓の表は、メーターを置く前の葉の見せ方の記録である。

| 風の表現 | 維持する初期値 |
|---|---|
| 小窓の内部座標 | 横 20、縦 10。UI の寸法は操作盤に合わせる |
| 葉の数 | 5 |
| 落下速度 | 3 + 0.3 × 風の絶対値 |
| 横流れ速度 | 1 × 風の値 |
| 単位 | 小窓の内部座標単位 / 秒 |

風と内部の速度の関係は変えない（TBD-14）。
無風は真下、強い風は横方向へ大きく流れる。

## 8.6 スプライトとフィールド

マシンは完全な横視点で、奥側の履帯や台座の天面を見せない。
本体、足回り、武器、VFX を別素材として重ねる。
撃つ武器の形を砲身に、もう一方の武器をサブ武器に描き、砲塔と足回りはスキンで変える（[43 章](./43-tank-skins.md)）。
回転原点と砲口は既存の物理へ合わせる。

フィールドは破壊可能地形の断面を主役にする。
土、草、岩は少数の色で描き、接地面と削れる範囲を明確にする。
遠景は低彩度の単純な形とし、地形と同じ強い輪郭を付けない。
装飾は地形マスクで切り、穴の上に草や岩だけが足場のように残らないようにする。
既存 8 マップの形とスポーンを維持し、背景を後から重ねる（TBD-26）。

砲弾は形と尾で区別し、発射者の主色を残す。
爆風本体は実際の半径に合わせ、煙や破片をダメージ範囲として読ませない。

## 8.7 素材の仕上げと導入

固定本体、履帯と標準砲、基本モーション、武器と VFX、UI、追加素材の順に作る。
大きな見本をそのまま atlas にせず、透過、palette、原点、方向、接続点を揃える。
生成画像の本体のばらつきは修正してから素材化する。

ガレージ、部屋、対戦、リザルトは共通の素材定義を参照する。
UI の枠はレイアウト部品で組み、スプライトを縦横別々に伸ばさない。

## 8.8 状態の可視性

手番、準備、選択、接続、低 HP は文字と形でも区別する。
残り 5 秒は注意色と短い音で知らせ、強い点滅に頼らない。
動きを減らす設定では画面揺れや装飾移動を抑え、状態の文字は残す。
再接続中は入力不能の理由と残り時間を示す。

PC とモバイルで、主文、警告、無効状態、長い部屋名、ソフトウェアキーボード表示中を確認する。
静止画の承認と操作の検証を分けて、完成を判断する。
