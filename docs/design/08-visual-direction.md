# 8. グラフィックの方向性

> 2026-09-09 再設計提案：本章の旧仕様から変更する範囲は[20章](20-global-game-redesign.md)の対応表を参照。カメラ・多人数・リアルタイム移動・世界公開の新しい実装目標は20〜23章を優先する。実装済みを意味しない。

> 2026-09-09: 新デザインの正本・色・パーツ構造・制作寸法は [16. 新デザインの制作基準](16-production-baseline-v2.md) を優先する。実装用素材は baseline-v2。旧案は履歴として区別し、新規生成の参照にしない。

[世界観](./00-world-and-experience.md)を配色、文字、画面、スプライトへ落とし込む。
本章は今後制作する画面の仕様であり、現在の黒地に緑文字の UI から置き換える目標である。
動作試験台と baseline-v2 の素材は実装済み。ゲーム本体の画面への導入は未実装である。

## 8.1 ドットと表示サイズ

地形と物理は **セル**、スプライトの原画は **art px**、画面上の寸法は **CSS px** で扱う。
三つを同じ単位に固定しない。
マップは 400 × 225 セルのまま維持する。

キャラクター、マシン、武器、VFX は共通のドット密度で制作する。
画像は nearest-neighbor で表示し、ぼかしや滑らかな陰影を焼き込まない。
UI の文字とボタンは物理セルの倍率から独立させる。

ガレージのプレビューは整数倍率を基本とする。
対戦ではマップの縦横比を保ち、使える領域に合わせて倍率を決める。
全マップ表示を維持し、操作盤の寸法は実寸で検証する（TBD-21）。
従来の左右 144 px パネルを新 UI の必須寸法にはしない。

新パックは共通192×160 art px、12 art px/cellで制作する。試験台のPC・モバイル表示を検証し、ゲーム内の最小対戦倍率は引き続きTBD-9で確認する。
HUD の顔だけを大きくして、機体内の顔が読めない問題を解決済みにしない。

## 8.2 色の役割

UI の配色とプレイヤーの色は別に管理する。
UI は深い青、明るい中立色、操作用のサフランイエローを基調とし、警告に暖色を使う。
以下は制作開始時の仮値であり、実画面で確認して確定する（TBD-22）。

| UI の役割 | 仮の色 | 使用箇所 |
|---|---|---|
| 背景 | #101C2C | 外周と HUD の下地 |
| 暗いパネル | #1B3044 | 操作盤と補助パネル |
| 主文 | #F6F1DF | 暗い面の文字 |
| 補助文 | #B9C9D3 | 状態説明 |
| 明るいパネル | #F6F1DF | ガレージの選択面 |
| 明るい面の文字 | #182B3A | 設定項目と説明 |
| 選択と主要操作 | #FFC345 | 選択の輪郭と主要ボタン |
| 注意 | #F1C46A | 残り時間の警告と未完了の準備 |
| 危険 | #F18B7B | 接続エラー、離脱、低 HP の補助表示 |

サフランイエローや暖色の塗りボタンには暗い文字を使う。
選択には輪郭とチェック、準備には文字、エラーには理由を添える。
無効状態も読める濃さを保ち、なぜ押せないかを近くに表示する。
配色だけで操作状態を区別しない。

主色と副色は現在の 7 色の識別子を維持する。
red、orange、yellow、cyan、blue、pink、purple の実値は protocol の COLOR_HEX を参照する。
UI の仮 palette でこれらの値を書き換えない。
部屋の主色の衝突ルールも維持する（TBD-10）。

| プレイヤー側の色 | 使用箇所 |
|---|---|
| 主色 | 本体の塗装面、足回り外装、名前の印、弾と VFX の識別部分 |
| 副色 | 本体・武器・履帯ハブのテラコッタのアクセント面 |
| 固定色 | キャノピーの枠と反射、金属、履帯、輪郭 |
| キャラクターの palette | 素体とオプション。マシンの色とは独立 |

本体の塗装は変えてよいが、形と寸法は固定する。
ガラスは独立した半透明の色面と光沢を持つ。搭乗者へマシンの塗装色を一括で掛けない。
主色と副色が同じでも、固定色と明暗で部品の境界が分かるようにする。

## 8.3 文字と部品

ドット文字は短いタイトル、見出し、装飾的な数値へ限定する。
説明、入力欄、部屋名、通信状態には読みやすい日本語の sans-serif を使う。
既存の DotGothic16 は短い見出しの候補とし、新フォントは配布条件と実寸を確認して決める（TBD-23）。

| 用途 | 初期の寸法方針 |
|---|---|
| 本文と入力 | 16 CSS px を基準 |
| 補助ラベル | 14 CSS px を基準。重要情報を小さくして収めない |
| 短いドット見出し | 使用フォントに合う整数倍率 |
| 残り時間と角度 | 等幅の数字。桁数で位置を動かさない |
| タッチ対象 | 高さと押下範囲は 44 CSS px 以上 |

パネルは単純な角丸の面とし、細い枠を画面全体へ重ねない。
押せるものは輪郭と余白で示し、押下時に浅く沈む反応を返す。
選択済みと hover を別にし、キーボードのフォーカスにも輪郭を付ける。

## 8.4 対戦前後の画面

ガレージでは搭乗したキャラクターとマシンを大きく見せる。
背景の整備道具は低彩度に抑え、輪郭を隠さない。
デスクトップは左にプレビュー、右に選択内容を置く。
縦画面はプレビュー、項目、主要操作の順にし、主要操作をスクロール領域から分ける。
プレビューは画面を圧迫しない高さとし、従来の下限 240 px を必須にしない。

通常画面は「キャラクター」「オプション」「足回り」「武器」「マシンの色」を要約する。
本体の形を選ぶ項目は置かない。
候補が一つしか実装されていない項目は、選択できるように見せず現在の素材を表示する。
比較時は角度、倍率、姿勢、背景を揃える。

ロビーは部屋名、マップの形、人数、観戦者数、状態、入室操作を読みやすく並べる。
部屋は両者の搭乗マシンを対にし、名前、武器、準備状態を同じ位置に揃える。
主色の衝突や開始できない理由は文字で示す。

リザルトは勝敗と決着理由を先に伝え、両キャラクターと成績を置く。
「部屋に戻る」と「ロビーへ」を明示し、未実装のランクや報酬枠を並べない。
リアクションが結果を読む時間や再戦操作を妨げないようにする。

## 8.5 対戦画面と風

対戦画面はフィールド、上部の状態表示、下部の操作盤で構成する方針とする。
上部は両者の小さい顔、名前、HP、中央に手番と残り時間を置く。
下部は左に移動と角度、右に武器と射撃をまとめ、左右入れ替えを維持する。
帯の高さと狭い横画面への配置は TBD-21 で検証する。

マシンには小さい識別印を添え、HUD の名前の印と主色を揃える。
キャラクター種や衣装の違いだけで自他を判断させない。
機体の名前と HP をキャノピーの上へ密集させない。

風は引き続き葉の流れで表し、数値と突風の通知は出さない。
風の小窓を操作盤の読みやすい場所へ置き、背景装飾とは分離する。
背景の旗や煙を別の風の計器として動かさない。

| 風の表現 | 維持する初期値 |
|---|---|
| 小窓の内部座標 | 横 20、縦 10。UI の寸法は操作盤に合わせる |
| 葉の数 | 5 |
| 落下速度 | 3 + 0.3 × 風の絶対値 |
| 横流れ速度 | 1 × 風の値 |
| 単位 | 小窓の内部座標単位 / 秒 |

風と内部の速度の関係は変えない（TBD-14）。
無風は真下、強い風は横方向へ大きく流れる。

## 8.6 スプライトとフィールド

マシンは完全な横視点で、奥側の履帯や台座の天面を見せない。
本体、足回り、武器、搭乗者、オプション、VFX を別素材として重ねる。
選択武器の形は変え、本体の形は維持する。
回転原点と砲口は既存の物理へ合わせる。

表情は自然な目、まぶた、頭、肩、手で作る。
カエルの白い喉と腹へ目や顔を追加しない。
低 HP の不安、大破の驚き、残骸の落胆を描き分ける。
別の種にも同じ状態名に対応する素材を持たせる。

フィールドは破壊可能地形の断面を主役にする。
土、草、岩は少数の色で描き、接地面と削れる範囲を明確にする。
遠景は低彩度の単純な形とし、地形と同じ強い輪郭を付けない。
装飾は地形マスクで切り、穴の上に草や岩だけが足場のように残らないようにする。
既存 8 マップの形とスポーンを維持し、背景を後から重ねる（TBD-26）。

砲弾は形と尾で区別し、発射者の主色を残す。
爆風本体は実際の半径に合わせ、煙や破片をダメージ範囲として読ませない。
状態、時間、接続点は [スプライトとモーション](./11-sprite-animation.md) に定める。

## 8.7 素材の仕上げと導入

固定本体とカエル、履帯と標準砲、基本モーション、武器と VFX、UI、追加素材の順に作る。
大きな見本をそのまま atlas にせず、透過、palette、原点、方向、接続点を揃える。
生成画像の顔の誤表現と本体のばらつきは修正してから素材化する。

ガレージ、部屋、対戦、リザルトは共通の素材定義を参照する。
UI の枠はレイアウト部品で組み、スプライトを縦横別々に伸ばさない。
制作形式とゲートは [アセット制作規約](./14-asset-pipeline.md) に従う。

## 8.8 状態の可視性

手番、準備、選択、接続、低 HP は文字と形でも区別する。
残り 5 秒は注意色と短い音で知らせ、強い点滅に頼らない。
動きを減らす設定では画面揺れや装飾移動を抑え、状態の文字は残す。
再接続中は入力不能の理由と残り時間を示す。

PC とモバイルで、主文、警告、無効状態、長い部屋名、ソフトウェアキーボード表示中を確認する。
静止画の承認と操作の検証を分けて、完成を判断する。
