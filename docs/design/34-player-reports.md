# 34. プレイヤー通報

対戦メニューから対象と理由（不適切な名前・迷惑行為・不正行為の疑い）を選ぶ。
参加者・観戦者とも送信できるが、自分自身・試合外のID・別試合への通報は拒否する。
自由記述や添付ファイルは受け取らない。

`room.report`は認証済みWebSocketで受け付け、RoomRuntimeの保存成功後に`room.reported`を返す。
同じ試合・報告者・対象の組合せは一度のみ。理由を変えても件数を増やさない。
1部屋の保持上限は256件。超過時は拒否し、古い通報を黙って捨てない。

保存内容はmatchId/reporterId/targetId/targetName/reason/createdAt/turnId/eventSeq。
対象名はサーバーのロビーから採用し、クライアント申告を信用しない。
通報は公開frame・部屋一覧に含めない。RoomSnapshot内部の`reports`へ保存する。
保持期間は7日。NodeのtickとDOのalarmで削除し、報告だけ残る空室も期限まで保持する。
UIに収集内容と保持期間を表示する。

運営は権限のあるSQLite/Node保存領域からreportsのみを取り出して確認する。
保存全体には接続情報を含むため、RoomSnapshot全体を調査資料として共有しない。
通報の受付は処分の自動実行や対応完了を意味しない。公開前に担当者・確認頻度・処分基準を決める。
外部へのメール/Slack通知や公開管理画面はこの実装には含めない。
