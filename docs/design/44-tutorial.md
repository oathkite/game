# 44. チュートリアル

初めて遊ぶ人に、戦車の基本の操作を一つずつ促して覚えてもらう。
盤面はターゲットチャレンジ（37章）の仕組みを使い、画面の下にメッセージボックスを重ねて「XXX すると YYY できます。XXX してみてください。」の形で次の操作を案内する。
物理、対戦用 engine、サーバー、通信プロトコルは変えない。

## 44.1 入口と戻り先

- 初回は、タイトル画面の「はじめる」でチュートリアルへ入り、終えると出撃準備（ロビー）へ進む。
- プラクティスのモード選択の先頭に「チュートリアル」を置き、いつでもやり直せる。
  終えるとプラクティスのモード選択へ戻る。
- 招待リンク（`?room=`）で開いたときはタイトル画面を通らないので、チュートリアルへ入らない。

初回の判定は次のとおり。

- 済みの印（`fortress.tutorial.v1`）、チャレンジの記録（`fortress.practice.v1`）、名前を入れたプロフィール（`fortress.profile.v1`）のどれも無ければ初回とする。
  名前かチャレンジの記録がある人は今までに遊んだ人とみなし、導入前から遊んでいる人には出さない。
- プロフィールがあるだけでは初回でないと言えない。
  `loadProfile` は最初の読み込みで playerId を残すために、名前の空の既定値を保存するからである。
  プロフィールの有無で判定すると、タイトルで離れた人は次に来たとき案内されない。
- 招待リンクから先に対戦した人は、名前を入れているので、あとで通常の入口から来ても案内しない。
- チュートリアルに入った時点で `fortress.tutorial.v1` を保存する。
  途中でメニューからやめても、次から強制しない。
- 保存できない環境では覚えられないので、起動のたびに初回として扱う。
  同じ画面の中では、タイトルへ戻って「はじめる」を押し直しても二度は案内しない。

画面切り替えのシャッターは対戦と同じ battle の向き（中央から開く）を使う。
ブラウザの戻るはプレイ中のメニューを開く（37.4 と同じ）。

## 44.2 盤面とメッセージボックス

- 地形は400×225セルの平らな床（y=180 から下）。
  開始位置は x=100、的は x=170 の1つ。風は0、装備は標準砲と三連弾。
- 開始時はターゲットチャレンジと同じ俯瞰から自機へ戻り、操作を受け付けられるようになってから案内を出す。
- 弾数は99にして実質無制限にし、外しても失敗にしない。
  床は厚さ45セルあり、歩いても場外に出ない。
  記録は残さない。
  自分の足元を撃ち続けて場外に落ちたときは、「弾切れ、または戦車が場外に落ちました。」と「再挑戦」を出し、盤面だけを作り直して同じ手順から続ける。
- 上の中央（チャレンジでは面の名前と残りの数を出す場所）には何も出さない。
  「チュートリアル 的 1」と出していたが、何を表すのか分かりにくいという所見を受けて 2026-10-05 に外した。
- メッセージボックスは画面の上の中央に重ね、左上の設定と全画面のボタン、右上の全体図を避ける。
  全体図の幅（220px、150px、100px）に合わせて左右に同じだけ空ける。
  縦持ちでは左右の間が狭いので、上のボタンと全体図の下の段に出す。
  横持ちのスマートフォンは盤面が低いので、本文とボタンを横に並べて高さを抑え、自機にかからないようにする。
  チャレンジのヒントの行と同じ高さの空の枠は残し、操作盤の位置を変えない。
- 文字はすべて 16px にする。
  画面の書体（DotGothic16）は 16px のドットで描かれていて、文字の平滑化を切っているので、12px や 14px では点が間引かれて潰れる。
  当初は本文を 14px、見出しを 12px にしていて、文字が潰れて読みにくいという所見があった。
- 非モーダルで、案内を出している間も操作を止めない。
  操作を促す手順にはボタンを置かず、促した操作でだけ進める。Space も発射にだけ効く。
  「次へ」で進む説明の手順は射撃操作を止め、ボタンにフォーカスを移す。
  このとき Space と Enter はボタンの押下にだけ効く。
- 「スキップ」は置かない（2026-10-05 のユーザー指示）。
  途中でやめるときは、プレイ中のメニュー（Esc、設定ボタン）の「チュートリアルをやめる」を使う。
  メニューには「チュートリアルに戻る」も置く。
- 促している操作のボタン（▲▼、◀▶、武器、パワーの目盛り、発射）を黄色の枠で点滅させる。
  動きを減らす設定では点滅しない。
- 文言はキーボードと画面のボタンの両方を書く。
  タッチ端末（`pointer: coarse`）ではキーを書かない。

## 44.3 手順

| 手順 | 促す操作と伝えること | 進む条件 |
|---|---|---|
| 1 導入 | 練習の流れを伝える | 「次へ」 |
| 2 角度 | ↑↓ か ▲▼ | 手順の始まりから角度が10度以上変わる |
| 3 移動 | ←→ か ◀▶。1回撃つまでに歩ける歩数に限りがある | 手順の始まりから5セル以上動く |
| 4 武器 | Q か E、または武器ボタン（縦持ちでは右下に無いので位置は書かない） | 選んだ武器が変わる |
| 5 目安の線 | パワーの目盛りを押すと目安の線を引ける。当たったパワーを覚えておくのに使える | 目盛りを押して線を引く |
| 6 発射 | Space か発射ボタンの長押し。目安の線を目印にする | 1発撃ち、再生が終わって次を撃てるようになる |
| 7 的を壊す | 角度とパワーを調整する。的が右にあること、左右の操作で向きも変わること、ドラッグで見回せることも伝える | 的が壊れ、再生が終わる |
| 8 風 | 対戦では風が弾を流す。角度メーターの下の風のメーターで向きと強さを確かめる | 「次へ」 |
| 9 制限時間 | 対戦では1回の手番に20秒（`TURN_LIMIT`）の制限時間があり、時間内に撃たないと撃たずに手番が終わる | 「次へ」 |
| 10 アイテム | ダブルシュートとテレポートを1試合に1回ずつ使える。撃つ前に武器の上のボタンで選ぶ | 「次へ」 |
| 11 完了 | プラクティスで復習できることを伝える | 「出撃準備へ進む」か「プラクティスへ戻る」 |

- 角度、移動、武器、発射、的の判定は、手順が始まったときの状態と今の状態を比べる純関数（`advanceTutorial`）が行い、入力のイベントには直接つながない。
  促していない操作をしても進まない。
- 目安の線は盤面の状態に残らない（パワーの目盛りの部品の中だけにある）ので、目盛りが線を引いたことを知らせ（`onPowerMemo`）、画面が次へ進める。
  目安の線はポインターでしか引けないので、キーボードだけの人はこの手順で止まる。マウスかタッチで目盛りを押す必要がある。
- 角度と移動は、変化が画面で見て分かる量になってから進める（10度、5セル）。
  1度や1歩で次へ進むと、押している間に案内が変わって読めない。
- 移動の手順では左へ歩いてもよい。
  左へ歩くと左を向くので、的の手順で的が右にあることと、左右の操作で向きが変わることを伝える。
  伝えないと、左を向いたまま的の反対へ撃ち続けてしまう。
- 風、制限時間、アイテムはこの盤面では試せない（風は0、時計は無く、アイテムはチャレンジで使えない）ので、的を壊したあとに説明を「次へ」で読む。
- 促す前に的を壊したら、残りの操作の手順を飛ばして風の説明へ進む。
  弾数は無制限なので、偶然当たっても困らない。

的の位置は、標準砲ならどの角度でもパワー42〜50前後で当たる距離にした。解法（開始位置、標準砲、46度、パワー45）を `apps/client/test/fixtures/challenge-solutions.ts` に置き、手順の判定と合わせてテストする。
手順の数、文言、進む条件の量は初期値で、初めての人に遊んでもらって調整する（TBD-tutorial-1）。

## 44.4 テスト

- `apps/client/test/tutorial.test.ts`：手順が促した操作だけで進むこと、説明の手順と目安の線は盤面の状態では進まないこと、再生の途中では的の手順を終えないこと、先に的を壊すと風の説明へ飛ぶこと、外し続けても失敗しないこと。
- `apps/client/test/tutorialSeen.test.ts`：初回の判定と保存、保存できない環境。
- `apps/e2e/world-tests/tutorial.spec.ts`：初回の「はじめる」から完了して出撃準備へ出ること、2回目はロビーへ直行すること、操作の手順にボタンが無いこと、目安の線で進むこと、メニューからの退出（初回は出撃準備、プラクティスからはプラクティス）、タッチ端末の文言。
- 既存の e2e は、新しいブラウザ文脈でも「はじめる」でロビーへ進むよう、各 config の `storageState` に済みの印を入れる（`apps/e2e/tutorialSeen.ts`）。チュートリアルの spec だけ空の状態で上書きする。
