# 38. 演出の強化

2026-09-23 のユーザー指示で、キャラクター、エフェクト、ローディング、ページ切り替えの演出を厚くした。
提案した 20 案（主要 12 案と候補 8 案）はすべて採用された。
以下の数値は初期値であり、遊んで調整する（TBD-28）。

## 38.1 36 章との関係

36 章は「装飾目的の動画・アニメーション制作は終了する」と定めていた。
本章の演出は、次の条件を満たすものに限って、その例外として認める。36 章の該当箇所も本章を参照するよう改訂した。

- 画像素材を使わず、`Graphics.rect` と CSS だけで描く（36 章の「画像依存を置き換える」は維持する）。
- 当たり判定、地形 mask、ターンの長さを変えない。`packages/sim` を触らない。
- 動きを減らす設定（`prefers-reduced-motion`）では、止めるか最後の姿だけを出す。
- 状態の把握に効く動き（誰の番か、どれだけ当たったか、地形がどう変わったか、何を待っているか）を優先する。雰囲気のための動き（C6、P1〜P4 の一部）は、ターンと操作を待たせない範囲に収める。

各案の「伝える状態」と 36 章上の区分（範囲内 / 境界 / 改訂が必要 / 要判断）は、提案の段階で整理した。

## 38.2 共通の作り方

- 時間は純関数にする。`経過時間 → 見え方` の関数を `game/tankMotion.ts`、`game/hitFeedback.ts`、`game/crumble.ts`、`game/trail.ts`、`game/edgeMarker.ts`、`worldUi/openingTour.ts` に置き、単体テストで数値を固定する。描画は `tankView.ts`、`projectileView.ts`、`renderer.ts` が行う。
- 乱数を使わない。粒の散り方は固定の表で決める（`DEBRIS_VELOCITIES` と同じ方式）。
- 位置はセルか art px（1/8 セル）で動かす。CSS は `steps()` を使う。

| C2 | パワーを溜める間、砲口へ点が集まる | 点の数は 1 + ⌊パワー × 5⌋（上限 5）、周期 350 ms。パワー 70% から点を黄色にし、砲身を 60 ms ごとに ±1 度震わせる | 点を止め、震えない |

| C5 | 撃破の明滅、3 連爆発、残骸 | 明滅 0〜260 ms（50 ms 周期）、爆発は 260、400、540 ms に始まり各 260 ms、560 ms で残骸、砲身は 18 度垂れる。残骸の煙は 700〜3200 ms | すぐ残骸 |

## 38.4 エフェクト

| ID | 演出 | 数値 |
|---|---|---|
| E1 | オンライン対戦にも練習と同じ着弾の演出 | 広がり 120 ms、明滅 300 ms、輪 100 ms、破片、画面揺れ、HP バーの減少、ダメージ段階別の白フラッシュ、外れの印 |
| E2 | 削れた縁のかけら | 削る前後の mask の差のうち、半径から 1.5 セル以内のセル。上限 24 個、400 ms で落ちる |
| E3 | 飛翔中の軌跡 | 練習は 2 ステップおき、オンラインはサーバーの位置列（4 ステップおき）の全点。新しい約 20 ステップを淡い緑、古い点をくすんだ緑 |
| E4 | 武器ごとの爆風の形 | レーザー弾は横に細い十字、掘削弾は下へ長い楕円、浮遊弾は二重の輪、ほかは円。削る範囲は sim の円のまま |
| E5 | 直撃の白黒反転 | ダメージ段階 3（25 以上）の着弾で、爆風が最大になった瞬間から 34 ms、爆風の円の中だけ |
| E6 | 画面の外で被弾した機体の印 | 画面の端から 16 px の位置に外向きの三角、120 ms で明滅 |
| E7 | 自分の前回の軌跡 | 次の自分の手番の間だけ、3 点おきに描く |

### E1 で決めたこと

- オンライン対戦の着弾は、これまで 300 ms の単色の円だけだった（`labReplay.ts`）。`hitFeedback.ts` の時間の流れを、サーバーが決めた着弾の時刻から再生する。
- 着弾から再生の終わり（`endsAt`）まで 590 ms（`IMPACT_TOTAL_MS`）に満たないときは、演出の全体をその長さに縮める（`impactClock`）。外れのターンは最後の着弾から 300 ms しか無いためである。サーバーの `endsAt` は延ばさない。延ばすとターンが長くなり、server と保存形式の変更になる。
- オンラインでは地形が着弾と同時に削れる（`terrainOps`）。練習のように爆風が最大になる 190 ms まで削るのを遅らせることはしない。地形の表示と当たりの確定を同じ瞬間に保つためである。
- 外れの印の位置は、可変サイズのマップでは実際のマップの大きさの端に寄せる（`missMarkAt` の `bounds`）。
- 破片のかけら（E2）は、一度に 9 個以上の削りが届いたとき（再接続など）には出さない。

### E4 の武器名

提案では `drill` を掘削弾と書いたが、ゲーム内の表示名は `drill` が貫通弾、`digger` が掘削弾である。下へ長い楕円は掘削弾（`digger`）に割り当てた。

### E7 で決めたこと

前回の軌跡は照準の助けになるので、難しさが変わる。**自分の画面だけに出し、相手と観戦者には見せない。** 次の自分の手番の間だけ表示し、手番が終わると隠す。

## 38.6 ページ切り替えとリザルト

| ID | 演出 | 数値 |
|---|---|---|
| P1 | 対戦へ入るときのシャッター | ふだんの移動は、進むときも戻るときも上から下りて上へ開く（従来の動き）。対戦へ入るときだけ、中央の横線が縦に開く。400 ms、8 段。当初は向きで左右や上下を変えたが、横に走る動きも下から上がる動きも不自然だというユーザーの指摘で、上から下りる形にそろえた |
| P2 | リザルトの段階表示 | 行を 90 ms おきに出し、数字を 8 段（1 段 40 ms）で数え上げ、勝者の冠を 2 回明滅。行と数え上げは全体 800 ms 以内に収め、8 人のときは行の間隔を 68 ms に詰める。クリックかキー入力で即座に全部を出す |
| P3 | START! の打ち出し | 1 文字 40 ms |
| P4 | YOUR TURN の走査線 | 1800 ms の表示のうち入りの 120 ms。走査線が入りを受け持つので、それまでの不透明度の立ち上がり（最初の 144 ms）は外した |
| C6 | リザルトの勝者と敗者 | 勝者の機体は、行が出てから 2 回跳ねる。そのため 800 ms を越えることがある（8 人で約 1170 ms）。敗者は灰色（静的なので動きを減らす設定でも適用） |

- プラクティスのリザルトは、シャッターが開ききる 400 ms 後から段階表示を始める。遅らせないと前半がシャッターの裏で終わるためである。オンラインのリザルトはシャッターを通らないので遅らせない。
- 待ち表示に出す工程は、実際に待っているものだけにする。部屋画面は「サーバーへ接続中」と「部屋を同期中」、オンライン対戦は「サーバーへ接続中」と「対戦データを受信中」、対戦画面の準備は「フィールドを準備中」。接続に失敗したときは、その文言を失敗の 1 行として出す。

## 38.7 確認したこと、していないこと

- 時間の流れはすべて単体テストで固定した（`test/tankMotion.test.ts`、`test/motionEffects.test.ts`、`test/labReplay.test.ts`、`test/labImpactView.test.ts` ほか）。
- 練習の CPU 戦で、描画の時計を 1/12 に遅くして、軌跡、爆風、縁のかけら、白黒反転が出ることを目で確かめた。緑の地形の上で暗い緑の軌跡が見えなかったため、軌跡の色を明るくした。
- シャッター 2 種、リザルトの段階表示と即時表示、START! の打ち出し、YOUR TURN の走査線、待ち表示を実ブラウザで確かめた。
- 部屋とオンライン対戦の e2e（`rooms-tests`、`world-network-tests`）は、今の UI に追従しておらず main でも失敗する。今回の変更の前後で失敗の一覧が同じであることだけを確かめた。
- 8 人対戦での密集時の読みやすさ、低い表示倍率での 1 art px の振動の見え方、演出の量が煩くないかは、実際に遊んで判断する（TBD-28）。
