# 19. 種族共通のフォルムと装備パーツ形式

2026-09-09。制作仕様 v1。利用区分は[17章](17-avatar-customization.md)、立ち絵の画像規格は[18章](18-avatar-portraits.md)を継承する。
本章は今後の素体・装備を設計する契約。現在の工房はbody・scarf・glassesの3レイヤーだけに対応しており、本章の汎用装備合成はまだ実装していない。

## 19.1 共通化するもの

**種族固有の顔を、共通の丸い二足体形と装備接続規格へ載せる。**
同じパーツ画像をすべての種族へ強制的に拡縮する仕様にはしない。同じ商品IDに種族・skin・姿勢別のfitを持たせる。

- 体形・接続点・装備の占有枠を共通化する。
- 目・口・耳・鼻・腹の模様は種族ごとに定義する。
- 立ち絵は少し右向きの前方3/4、搭乗時は真横の右向き。
- 立ち絵の密度は元デザイン案を基準とする。搭乗時のドット数へ制限しない。
- 外見は機体性能・当たり判定へ影響しない。本人専用KITAの素材・組み合わせを公開商品へ流用しない。

## 19.2 フォルムの共通ルール

最初の共通体形を `round-biped-v1` とする。追加種族はこの体形へデフォルメする。
カエルの顔を別動物へ貼るのではなく、同じ世界の体格で各種族を描く。

基準は装備なしneutralの足裏から頭頂までの高さH。耳・角・髪・尻尾はHに含めず、別の追加シルエットとして記録する。

|部位|共通の目安|許容する種族差|
|---|---|---|
|全体|丸い胴体、低い重心、短い二本脚。頭と胴の境界は滑らか|顔と胴が連続するカエル型、頭が少し分かれる動物型|
|顔を配置する上部|Hの上側約35〜40%。数値上の顔領域ではなく構図の目安|目の間隔、口吻、耳の有無。実際の目・口は別の保護領域|
|胴|胸〜腰に丸み。neutralの胴幅はHの45〜65%を目安|腹の模様、毛・鱗などの簡潔な輪郭|
|脚|股下から足裏までHの15〜22%を目安|丸足、短い爪、ひづめ。長い人型脚にしない|
|腕・手|二本の短い腕。小さな手袋状の手。腕を下げると手先が腰付近|指の本数を細部で強調しない。握る・開く形を共有|
|足|左右の足裏と接地点を持つ。靴を履いても基準線を維持|指・爪の形は靴の下へ隠せる|
|追加特徴|耳・角・尻尾は頭・胴の共通体積を置き換えない|頭装備との競合、背面パーツとの競合を明示|

比率は新規素体のデザイン審査用の目安であり、喜びやうつむきのコマへ一律に強制しない。
既存KITAの形を数式へ合わせて再変形しない。極端に細長い体・四足・蛇型・多腕はこの規格外とし、別bodyProfileと対応パーツを制作する。

portraitは192×224 artpx、foot=[96,208]。通常の素体Hは150〜175 artpxを目安とし、頭上と左右へ装備・動作の余白を確保する。
neutralの足元と縮尺をポーズ間で固定する。悲しみで頭が下がっても拡大して高さを合わせない。
耳を含めて枠を超える場合、全員の体を縮めるのではなく、その種族の耳のデフォルメや装備形状を調整する。

battleは192×160 artpx、pilotSeat=[55,97]。固定キャノピーに収まる座位を別途描く。
portraitの衣服・靴がそのまま搭乗時に見えるとは限らない。腰下・足元・操縦桿に隠れる部位を明示する。

## 19.3 装備枠

UI上は「顔」「体」「手」「足」の4グループ。データは次の9スロットで管理する。
left/rightは画面上の左右ではなくキャラクター本人の左右。前方3/4でのnear/farはフレームの描画順へ変換する。

|UIグループ|slot ID|例|接続点|
|---|---|---|---|
|顔|head|帽子、ヘルメット、髪飾り|head-top|
|顔|face|メガネ、バイザー、マスク|face-center|
|体|neck|スカーフ、蝶ネクタイ、首輪|neck|
|体|body|服、ベスト、胸当て|chest・waist|
|体|back|リュック、マント、小さな羽|back|
|手|hand-left|左の手袋、腕輪、手持ち小物|wrist-left・grip-left|
|手|hand-right|右の手袋、腕輪、手持ち小物|wrist-right・grip-right|
|足|foot-left|左靴、足飾り|ankle-left・sole-left|
|足|foot-right|右靴、足飾り|ankle-right・sole-right|

各slotは1アイテムまで。空は未装備。
一組の手袋・靴は1つの商品IDで左右2slotをoccupiesに指定する。左右別商品も可能だが、最初の制作ではペアを基本にする。
フード付き服はhead+body、全身スーツはbody+hand-left+hand-right+foot-left+foot-rightなど複数枠を占有できる。
新しく装備するアイテムとoccupiesが重なる既存アイテムは、アイテム単位で外す。ペアの片方だけを残さない。UIで外れる品を示す。

blockedSlotsはskinが物理的に装着できない枠。耳のある種族全体をhead不可にするのではなく、耳対応fitの有無で判断する。
装備同士の形状干渉はconflictsWith（item IDの組）へ記録する。重複slot以外の競合だけを登録し、判定は対称に扱う。

## 19.4 素体とパーツの納品

### 素体

speciesはid・bodyProfileを持ち、skinはspeciesIdとpresentation別の画像を参照する。
各使用フレームへ次を登録する。推測した顔領域を別種族へコピーしない。

- 足元基準、縮尺、頭頂・胸・腰・左右手首・握り・左右足首・足裏・背中の接続点。
- 実際の目・瞳・口の保護マスク。口が独立して見えない種族は口領域を空にする。腹や喉を顔として登録しない。
- 手足・胴・耳・尻尾の重なり順。服や靴で隠す領域のマスク。
- ポーズID、フレーム番号、画面上のnear/far。左右反転時も本人の左右IDを保つ。

接続点は整数artpx。位置だけでなく、接続辺や接触範囲を小さなマスクで持てる。
マスクは同じキャンバスのindexed PNG、index0=対象外・index1=対象。色の近さから範囲を推定しない。
現在のeyeAreas矩形は既存工房用として保持する。新規fitのマスクと併存期間を設け、検証なしに置き換えない。

### パーツ

[記入例](templates/avatar-part.example.json)は制作計画の例であり、実在する納品済みパーツではない。

|項目|形式・意味|
|---|---|
|avatarPartVersion|1。このパーツ形式のversion。既存portrait manifestとは別|
|id / displayName|不変のitem IDと表示名|
|group|face / body / hands / feetのいずれか|
|occupies|上表のslot ID配列。重複不可|
|availability|public / owner-only。owner-onlyにはgrantKey必須|
|bodyProfile|対応する共通体形|
|conflictsWith|明示的に競合するitem ID配列|
|paintChannels|許可した色面。未対応なら空。目・輪郭・透明indexは対象外|
|fits|skinIdごとのportrait / battle対応。種族名だけで互換としない|
|fit.status|planned / draft / approved|
|fit.visibility|visible / occluded。見えない理由をreasonへ記載|
|fit.poseSet / frames|必要ポーズ集合、各フレームのlayer・anchor・offset・mask参照|
|fit.source / digest|原画・PNG・ORA・登録データの出典とSHA256。planned時はnull、納品時必須|
|review|接触・切れ・遮蔽・組み合わせの検査結果と目視承認|

同じ画像を複数skinで使う場合もfitを個別に登録する。同じ服に種族別の襟・袖の形を持たせてよい。
「対応bodyProfileが一致」は候補として試着できる条件であり、対応済みの証明ではない。
既存のメガネ・スカーフは本人用item IDと利用区分を保持して移行する。

### フレームの記入形式

framesの各要素は次の形を使う。以下のID・パス・数値は構造説明用で、納品済み画像を指さない。
同じposeに複数フレームがある場合はframeを0から連番にする。動作時間は素体側clipの値を継承する。

```json
{
  "pose": "neutral",
  "frame": 0,
  "layers": [
    {
      "id": "glove-left",
      "slot": "hand-left",
      "file": "glove-left.png",
      "atlasFrame": 0,
      "anchor": "wrist-left",
      "partAnchor": [68, 142],
      "offset": [0, 0],
      "insertAfter": "hand-left",
      "contactMask": "contact-left.png",
      "bodyHideMask": "hide-left.png"
    }
  ]
}
```

fileと各maskは納品manifestからの相対パス。atlasFrameは左から横並びの0始まり。1列の横atlasを基本とし、frameSizeはpresentationから取得する。
配置式は「素体anchor座標 − partAnchor + offset」。partAnchorはパーツのフレーム内整数座標、offsetは最終位置の整数補正。
insertAfterはそのフレームの素体segment IDを参照する。存在しない部位・接続点の参照はエラー。
同じsegment直後に複数パーツが入る場合の優先順は、foot → hand → body → back → neck → head → faceとし、左右は当該segmentの順序に従う。
この順序で成立しない組み合わせは専用fitまたはconflictsWithで扱い、任意のz値で解決しない。

不要なmaskはnullを指定する。bodyHideMaskがある場合は対象segmentをinsertAfterと同じ部位に限定する。
複数部位を隠す全身服は部位ごとにlayerを分ける。体全体への不透明マスク1枚で他部位を消さない。
visibleのfitを納品するにはposeSetの全フレームと全占有部位を用意する。occludedのfitはframes=[]とreasonを必須にする。
画像は32色indexed PNGとORA、透明index0。装備paletteとpaintChannelsを別々に持ち、素体の色替えで装備まで変色させない。
plannedはsource/digest=null・frames=[]を許可するが、draft以降のvisibleは許可しない。approvedへの変更には対象digestに対応した自動検査と目視承認が必要。

## 19.5 レイヤーと装着

フレームの基本順序は「背面装備 → 奥の手足 → 胴 → 衣服 → 頭・首・顔装備 → 手前の手足」。
各素体セグメントの直後へ対応する服・手袋・靴を挿入する。腕組みなどで順序が変わる場合はフレーム単位の順序を記録する。
マントの背面と留め具など、1アイテムに複数描画レイヤーを持たせてよい。装備数と描画レイヤー数を同一視しない。

- 共通frameSizeでフレームを納品し、透明余白を含めて接続位置を保存する。
- パーツ側anchorを素体側anchorへ合わせ、整数offsetのみで配置する。非等方拡縮・自動回転で無理に合わせない。
- 違う角度や握りの絵が必要なら専用フレームを描く。左右非対称パーツは反転用フレームも納品する。
- 服・靴の下へ素体がはみ出す場合は、そのfitのbodyHideMaskで隠す。元の素体を消して保存しない。
- bodyHideMaskの適用対象は素体のみ。他装備やキャノピーを削らない。
- 目を見せるメガネと、意図的に顔を隠すマスクは扱いを分ける。標準は目の保護。遮蔽装備はcoversFeaturesへ対象を列挙し、目の代わりに腕・姿勢で勝敗が読めることを目視承認する。
- 搭乗時は全身合成の前後に座席・車体前面・ガラス・枠を重ねる。手持ち品は操縦を妨げるならbattleではoccluded（収納）とし、商品説明にも明示する。
- 靴・足飾りが座席下に完全に隠れる場合はbattle.visibility=occluded。欠損フレームを黙って非表示にはしない。

## 19.6 ハーネスの受け入れ基準

新規パーツの量産前に以下を工房へ実装する。現行の3レイヤー検査だけで汎用互換性を合格にしない。

|段階|必須検査|
|---|---|
|形式|version、ID、slot、占有重複、skin所属、参照・digest、PNG/ORA、frame寸法|
|互換|skin/presentationのfit、blockedSlots、複数枠占有、対称なconflictsWith|
|接続|全フレームでanchor存在・整数座標・パーツ接触・bodyHideMask範囲|
|表情|保護された目・口の遮蔽なし。意図的遮蔽はcoversFeaturesと目視承認が必要|
|描画|左右・near/far・背面/前面の順序、輪郭残り、靴の足裏、全ポーズの切れ|
|搭乗|全9状態・固定キャノピー・8武器・左右・仰角・車体反動・無彩色残骸|
|組み合わせ|単品、裸、各slotの承認済み標準品との組、競合ペア、販売するpresetの全組み合わせ|
|動作|装備替え・種族替え・ポーズ替え後の再生、導入→idle、loop境界、静止fallback|
|権限|本人用の公開preset混入禁止。装備保存・対戦参加はサーバー側所有権確認|
|記録|実施したskin/item/pose/frame一覧、未検証の組み合わせ、承認対象digest|

組み合わせ数が大きくなるので、未実施を合格として扱わない。異種族共用をうたう商品は、宣言した全skinで検証する。
新種族は素体だけで承認せず、帽子・顔装備・襟付き服・手袋・靴の試着セットで確認する。
手袋・靴は本来の手足を完全に置換する場合があり、単純な画素交差だけでは装着を判定できない。接続マスク・足裏と目視を併用する。

## 19.7 導入順

1. KITAのneutral/happy/sadに共通接続点と部位マスクを登録する。
2. 工房を9slot・複数レイヤー・占有/競合の切り替えへ拡張する。
3. 本人用と混同しない試作用の帽子・服・手袋・靴を1組ずつ制作し、規格を試す。
4. 別種族の試作用素体1体で同じ商品IDの別fitを制作し、互換範囲を検証する。
5. portrait承認後に搭乗9状態へ展開し、公開カタログ・権限処理へ組み込む。

本章では新規パーツ・別種族の画像制作や汎用rendererの実装完了を意味しない。
