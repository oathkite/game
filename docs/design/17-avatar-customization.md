# 17. キャラクターのアバター・カスタマイズ仕様

2026-09-09改訂。種族は固定せず、将来ほかの種族を追加できる余地を残す。追加する種族と制作時期は未決定。本人専用アバターの扱いは維持する。
汎用の体形・顔/体/手/足の装備形式は[19章](19-avatar-form-and-parts.md)を正本とする。本章は制作・実装用の仕様であり、所有権確認やカタログUIは未実装。

## 17.1 本人専用アバター

現在の黄色いカエル＋オレンジスカーフ＋青いメガネは、ユーザー本人の大切なアバターとして専用扱いにする。
一般プレイヤーの初期アバター、販売商品、配布特典、未知データのfallbackに使用しない。
本人専用preset IDを`kita-personal`、skin IDを`frog-kita-personal`とする。実アカウントIDや認証情報はドキュメントへ記載しない。

|対象|扱い|
|---|---|
|本人用の外見|黄色い素体＋現オレンジスカーフ＋現青いメガネを一式として保持|
|既存asset ID|pilot-frog、glasses-blue、scarf-orangeを本人用素材として予約|
|原資料|初期3D資料を本人用デザインの正本として保持。一般用へそのまま転用しない|
|制作プレビュー|本人用素材の確認用途として継続使用可。公開プレイヤー用のdefaultを意味しない|
|一般プレイヤー|別のカエル素体・配色・装備を新規制作。デザインは未決定|

専用アバターを一般スキンの単なる色違いとして公開しない。現メガネやスカーフも別売り・配布へ自動転用しない。
メガネやスカーフという種類そのものを禁止する意味ではない。一般用は区別できる別デザインを制作し、本人用との混同を確認する。
黄色という色自体を全面禁止する仕様ではなく、本人専用の外見・素材一式を保護する。
一般用の組み合わせで専用外見を再現できないことを、素材と配色の組み合わせで確認する。
本人用データへのアクセスは所有権と分けて考える。描画用画像が見えることは装備権限を意味しない。

## 17.2 カスタマイズ単位

|単位|内容|
|---|---|
|species|顔の構造・体形を定義する。初期登録はfrog。追加種族を登録可能な形式とする|
|skin|各種族の模様・素体一式。搭乗全9状態とportraitを用途別に納品|
|paint|スキンが許可したbodyとmarkingの色面。車体色とは独立|
|accessory|顔・体・手・足の4カテゴリ、内部9slot。複数枠を占有するアイテムを許可。未装着可|
|preset|skin・paint・装備の組み合わせ。本人専用などの利用区分を持つ|

種族と、その種族に属するスキン・配色・衣装・装備を追加できる。機体の性能・当たり判定・キャノピーの寸法は変えない。
素体と一体の衣装が首を占有する場合、skinのblockedSlotsへneckを指定する。着脱する衣装は装備側のoccupiesを使う。帽子・背中・手持ちを含む枠と競合は19章へ定義する。
本人用は既存の固定配色を維持する。一般用のペイント範囲は新しい素体で定義する。

## 17.3 共通制作規格

- 搭乗用は真横の右向きを基準とする。portraitは少し斜めの前方3/4。非対称装備は専用反転フレームを納品する。
- 192×160 artpx、12 artpx/cell、pilotSeat=[55,97]。全ポーズの縮尺を固定する。
- 種族ごとの自然の目と体の模様を分離する。カエルは頭上部の目と喉・腹を区別し、腹へ顔を描かない。他種族へカエルの顔配置を流用しない。
- 既存スキンはheadAnchor、neckAnchor、frameFaceAreasを全使用フレームへ登録する。汎用パーツ導入時は19章の部位別接続点・保護マスクへ拡張する。
- 腰は共通車体前面に隠れ、頭と装備は共通キャノピー内に収まる。素体だけを非等方拡縮しない。
- 元画像、プロンプト、参照資料、model ID、SHA256、indexed PNG、編集用ORA、asset manifestを保存する。
- 画像生成はGPT Image 2.5。本人用原資料の一般素材への転用をプロンプトで指示しない。
- portraitや立ち絵は別成果物で密度も別。KITAの代表静止3ポーズは18章、その他の未制作素材は未制作と表示する。

## 17.4 全9状態

|状態|表現と制約|
|---|---|
|idle|呼吸・まばたき|
|move|操縦中の小さな揺れ|
|fire|通常着座を180ms保持する非loop clip。のけぞらず、車体最大2 artpxの反動に追従|
|hit|短い驚き。終了後idleまたはlow-hpへ|
|low-hp|不安や疲労。自然の目の位置を維持。上昇煙3本|
|fall|緊張した姿勢。接地後landへ|
|land|450msの着地・土煙|
|destroy|驚きから脱力。600msでwreckへ|
|wreck|落胆。描画時に無彩色、車体8 artpx沈下、砲身18度下向き、煙4本|

フレーム数自体は16固定にしない。clip・顔領域・接続点を一式で差し替え、別スキンの接続点を残さない。
残骸用に無彩色の原画を複製しない。装備は状態変化でも対応する身体部位の接続点へ追従する。

## 17.5 装備と描画順

既存工房はface（メガネ）とneck（スカーフ）の3レイヤー合成に対応する。
汎用仕様は19章の9slot・occupies・skin/presentation別fitへ拡張する。同じ商品でも種族別の装着画像を持てる。未対応skinへ自動拡縮して適用しない。
旧fits（skin ID→asset ID）は搭乗用のみの対応表。portraitの承認や汎用パーツの対応済みを意味しない。
既存の描画順「座席 → 素体 → neck → face → 車体前面 → ガラス → 枠 → 武器」は維持し、汎用renderer実装時に19章の部位別レイヤーへ置き換える。

## 17.6 ペイント形式

一般用スキンはbody（主色）とmarking（腹・模様）のうち許可した領域だけ色替えする。目・瞳・口・輪郭は固定。
初回はプリセット色IDから選び、任意HEX入力は作らない。アクセサリーは完成配色の別デザインとして扱う。
現在のpilot/accessoryはfixed paletteであり、汎用色替えは未実装。

追加assetメタデータ`avatarPalette`はversion=1、channelsにbody/markingを持ち、それぞれ`{index, tone}`の配列とする。
indexは実palette内の整数、toneは-1〜1の有限数。透明index0や目・輪郭のprotectedIndicesと重複させない。
channels外は固定。目と腹が同じRGBでも別indexを使い、RGB類似度で色替え領域を推測しない。
明部は白、暗部は黒へ混合する。validatorとrendererの対応を同時に追加し、車体用paletteRolesへ無断混在させない。
カタログのpaintChannelsは領域名→許可paint ID配列、保存データpaintは領域名→選択paint ID。未対応なら空オブジェクト。

## 17.7 カタログと利用権限

[カタログ記入例](templates/avatar-catalog.example.json)は旧face/neck向けv1設計例であり、実行中の設定ファイルではない。汎用パーツは19章とパーツ記入例を使用し、旧fitsへportraitや複数枠を詰め込まない。
IDは小文字英数字とハイフン。公開後に同じIDを異なる外見へ再利用しない。

|項目|必須内容・制約|
|---|---|
|species|id、displayName。登録種族の一覧。現時点の記入例はfrogのみ|
|publicDefaultPresetId|一般用の承認済みpreset ID。未制作の現在はnull。本人用を指定不可|
|skins|id、speciesId、pilotAssetId、blockedSlots、paintChannels、availability|
|accessories|id、slot、fits、availability。fitsはskin ID→asset ID|
|presets|id、skinId、paint、accessories、availability|
|availability|publicまたはowner-only。owner-onlyはサーバー側の許可に対応するgrantKeyを必須とする|
|appearance|presetId、speciesId、skinId、paint、accessories。所有権や価格をクライアント申告値として持たない|

本人用presetと構成素材すべてにowner-onlyを付ける。preset IDを外して構成素材を直接指定する抜け道も認めない。
grantKeyはサーバー側で本人の認証済みアカウントへ紐づける識別子であり、秘密鍵やクライアントの所有証明ではない。
表示名・nickname・任意localStorageフラグで本人判定しない。装備保存と対戦参加時に、skinと装備を含むすべての権限をサーバーで確認する。
未所有品の一般向け試着にも本人専用を含めない。一般用の販売・試着ルールとは分離する。
不正な外見指定は拒否する。未知データの表示fallbackは承認済み一般用を使用し、未制作の間は「外見未設定」とする。
公開リリースまでに一般用defaultと本人認証・専用権限検査を実装する。現在の制作ツールにアクセス制御済みとは扱わない。

## 17.8 検証ハーネスへの追加要件

以下は今後の追加検査。現在の実装完了を意味しない。

- カタログのID重複、参照切れ、speciesとskinの所属一致、skinと装備fit、blockedSlotsを検査する。
- public preset/defaultからowner-only素材を参照したら失敗する。
- 一般利用者による本人用preset・skin・装備の直接指定、nickname偽装を拒否する。本人は正常に装備できる。
- 色領域の重複、固定部混入、目や輪郭の変色を検査する。
- species×skin×対応装備（なし含む）×許可色×9状態を検査し、未実行範囲もreportへ記録する。
- 全8武器・左右・仰角10〜90度・坂・反動で、目の保護、装備接触、搭乗位置を確認する。
- 本人用との見た目の混同・再現性は合成コンタクトシートで目視する。最小対戦倍率はTBD-27。

## 17.10 種族追加の境界

別種族を追加しても、共通の座席・キャノピー・9状態・機体性能は維持する。種族ごとに顔領域と接続点を登録し、装備のfitsはskin単位で明示する。追加種族は19章のround-biped-v1を基本とし、共通形状・装備枠を検証する。汎用rigや選択UIの実装は別工程。
種族選択を実装する際は、その種族の利用可能なskinへ切り替え、非対応装備の解除を画面に示す。本人用skinや素材へ自動fallbackしない。一般用の初期種族・デザインも未決定とし、現在のカエル記入例を公開defaultとは扱わない。
