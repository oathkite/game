# 0. 世界観と体験の方向性

2026-09-09 改訂。
本章は承認された横視点のマシンとカエルを基準にした制作指針であり、新しい UI や素材の実装完了を示すものではない。

## 0.1 ゲームの中心

FORTRESS は、小さなパイロットたちが自分のマシンに乗り、風と地形を読んで一発を競う、ブラウザの 1 対 1 ターン制砲撃ゲームである。
キャノピーの中に選んだキャラクターが見え、発射で踏ん張り、被弾で驚き、敗北で肩を落とす。

体験の柱は三つとする。

1. **一発を読む楽しさ**：風、角度、地形、武器を判断し、狙った場所へ当てる。
2. **搭乗者への愛着**：自分のキャラクターと装備が、ガレージから対戦まで同じ姿で現れる。
3. **組み合わせる楽しさ**：共通本体に、足回りと武器、別のキャラクターを組み合わせる。

親しみやすい見た目と、狙いを定める緊張感を同時に作る。
弾道の予測線や風の数値は追加せず、既存の読み合いを維持する。

## 0.2 舞台のトーン

舞台は、パイロットたちのガレージと、マシンを走らせる競技フィールドを軸に表現する。
丸みのある金属外装、透明なドーム、短い反動、土煙で、小さな機械を操縦する楽しさを出す。
整備台や部品トレーなどの背景要素は操作の意味を補い、キャラクターを隠さない密度にする。

大破は競技上の敗北として見せる。
キャラクターのリアクションは不安、驚き、落胆で表し、身体の損傷を描かない。
最終的な退場方法は TBD-25 とする。
見本の「機内でしょんぼりする」はその候補であり、脱出方法を確定したものではない。

固有の国、戦争、組織、通貨、ランクの物語は追加しない。
世界名やキャラクター名は、素材制作で必要になった時点で決める。

## 0.3 固定するものと増やすもの

| 対象 | 方針 |
|---|---|
| 本体 | キャノピー、台座、座席を含めて同じ形と寸法を使う |
| 視点 | マシンは真横。坂への傾きと砲身の回転は画面内の回転 |
| 初期キャラクター | 種族は将来追加可能。提供された黄色いカエル一式は本人専用。一般用は別途制作 |
| 別のキャラクター | 種ごとに素体、搭乗姿勢、表情、装備の接続点を持つ |
| オプション | メガネとスカーフを素体とは別に着脱する |
| 足回り | 履帯を基準に、車輪や機械脚などを追加できる |
| 武器 | 現在の 8 種を基準に、武器本体と VFX を組として追加できる |
| 外見と性能 | 外見の選択では性能を変えない方針。新武器の性能は別のルール変更 |

キャラクターの体格を収めるために、本体を拡縮したり形を変えたりしない。
カエルの白い喉と腹は体の色面であり、そこへ目や顔を描かない。
この規則は小さい HUD の顔画像にも適用する。

## 0.4 画面ごとの役割

| 画面 | プレイヤーが行うこと | 主役 |
|---|---|---|
| ガレージ | 自分の姿と装備を確認し、練習か対戦へ進む | 搭乗マシンとキャラクター |
| カスタマイズ | 何が変わるかを見比べる | 同じ角度と倍率の候補 |
| ロビー | 入れる部屋を探すか、自分で作る | 状態とマップの形 |
| 部屋 | 両者の準備を確認する | マシン、名前、武器、準備状態 |
| 対戦 | 手番を把握し、風を読んで狙う | 地形、マシン、弾、照準、時間 |
| リザルト | 結果を理解して次の一戦を選ぶ | キャラクターの反応、結果、再戦操作 |

ガレージでは大きなプレビュー、対戦では搭乗姿とコンパクトな顔表示で本人を認識できるようにする。
HUD の顔表示だけで、機体内の顔が読めない問題を解決済みにしない。

## 0.5 UI のトーンと言葉

深い青を土台に、明るい中立色の文字と控えめなサフランイエローの操作色を使う。
ガレージの主要パネルは暖かい明色とし、対戦 HUD は暗い不透明な面に情報を集める。
色の初期案は [グラフィックの方向性](./08-visual-direction.md) にまとめる。

ドット絵はキャラクター、機械、地形、VFX に使う。
説明文や通信エラーは読みやすい通常の文字で組む。
UI の輪郭は単純な角丸とし、ドット装飾は見出しや選択状態へ限定する。

呼称は「キャラクター」「マシン」「本体」「足回り」「武器」「オプション」で統一する。
操作は「プラクティス」「ロビーへ」「準備完了」「対戦開始」「部屋に戻る」と短く具体的に書く。
手番は文字で明示し、表情だけに判断を任せない。
通信失敗や無効入力も平易な日本語で伝える。

音は発射、着弾、操作状態を中心にし、現行の通知タイミングと消音を維持する。
新しい楽曲や環境音は別の素材制作として扱う。

## 0.6 課金と制作の境界

キャラクターの外見を課金要素にできる構造を用意する。
スキンとペイントの方式、無料範囲、価格、販売方式は未決定である。
未提供のショップや通貨残高を現行 UI の必須要素にしない。

販売を導入するときはアカウント、所有権、購入の復元を合わせて設計する。
端末保存の外見 ID を所有証明にしない。
ガレージ、部屋、対戦、リザルトで同じ外見を表示する。

制作では、本体の一致、顔の正しさ、実寸の可読性、操作状態の識別を確認する。
描画変更で物理と通信の契約を変えない。
素材の形式と検証手順は [アセット制作規約](./14-asset-pipeline.md)、未決定事項は [一覧](./99-open-questions.md) を参照する。
