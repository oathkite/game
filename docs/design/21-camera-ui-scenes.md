# 21. カメラ・UI・開始ページ・シーン演出

2026-09-09 / 新仕様の設計提案。実装済みを意味しない。全体方針は[20章](20-global-game-redesign.md)。

## 21.1 座標と大きさ

物理cell、素材art px、画面CSS px、描画bufferのdevice pxを分離する。
ワールド座標はマップ左上原点、右が+x、下が+y。カメラ中心をC、表示領域中心をV、倍率をsとする。
画面位置は `screen = (world - C) * s + V`。pointer入力はこの逆変換を使う。
HUDと入力対象はCSS pxで配置し、カメラやDPRで拡大縮小しない。

通常視点のsは端末のレイアウト区分で選び、マップ寸法・生存人数・弾の距離では変えない。
初期案は標準6、狭い横画面4.5 CSS px/cell。端末回転では区分を再評価し、自機または注視点を維持する。
192×160 art px / 12 art px per cellのフレームなら、標準96×80 CSS px、狭い画面72×60 CSS pxになる。
これは透明余白を含むフレーム寸法であり、本体や顔の可読寸法ではない。実素材の不透明領域で確認する。
判定半径3cellは維持し、素材の外周がhitboxより大きい部分を照準テストで説明可能にする。

最小横画面667×375、代表844×390、タブレット1024×768、PC1440×900で比較する。
低い画面ではHUDを詰め、マップ全体を縮めない。対戦は横持ちを推奨し、縦持ち時は回転案内と観察を提供する。
回転でサーバーの手番は止めない。入室前に横持ちの操作確認を行えるようにする。

2.5画面の基準は、PCの有効ワールド領域幅1200 CSS px / s=6 = 200cell。
例として幅500cellが2.5画面になる。モバイルでは見える範囲が狭く、必要なパン量は増える。
端末ごとに物理マップを変える設計は禁止。同じ試合は全員同じMapSpecと地形を使う。
幅400の旧マップでもカメラ導入は可能。幅500への拡張は射程検証後に行う。

垂直方向も自由に移動できる。地形boundsと、弾道を追うための上空boundsを別に持つ。
カメラは有限のpresentation boundsへclampし、世界がviewportより小さければ中央寄せする。
上空boundsを越えた弾は方向マーカーで示す。カメラ端を物理的な弾の消滅条件にしない。

## 21.2 カメラの状態

カメラはクライアントの表示状態。対戦state/hashには含めない。

| 状態 | 追う対象 | 入る条件 | 出る条件 |
|---|---|---|---|
| TurnFocus | 手番機体、発射方向に少し余白 | 試合開始・新手番 | 300ms移動後FollowActor |
| FollowActor | 手番機体。中央60%のdead zone内では固定 | 自機へ戻る、追従再開 | パンでManual、発射でShotFollow |
| Manual | ユーザー指定中心 | スワイプ・端スクロール・ミニマップ | 戻るボタン、新手番、発射時の追従設定 |
| ShotFollow | 代表弾、続いて主要着弾 | 発射 | 再生完了、または手動パン |
| ImpactHold | 主要着弾地点 | 主要弾着弾 | 約500ms後、次の追従対象へ |
| Overview | ミニマップの拡大パネル | 全体図ボタン | 閉じる・地点選択 |

新手番では注目を手番機体に戻す。観戦者は「手動視点を維持」を選べる。
発射時の弾追従は初期ON。Manual中でもONなら発射へ切り替え、OFFなら画面外マーカーだけで知らせる。
弾追従中も手動操作で即座に上書きできる。自動復帰の無操作タイマーは設けず、勝手に視点が戻るのを避ける。
右下に「自機へ」「手番へ」「弾を追う」を状態に応じて表示する。自機脱落後は生存する味方を候補にする。

カメラ移動はdelta timeに基づく補間で、FPSが異なっても同じ所要時間にする。
通常300ms以内、長距離でも600ms以内の移動を初期値とする。reduced motionでは短いfadeか即時切替。
輪郭の揺れを防ぐため最終描画でdevice pixelへ位置を揃え、simulation座標自体は丸めない。

複数弾は中央の代表弾を第一候補とし、消滅時に残った弾へ一度切り替える。毎フレーム平均位置へ飛ばない。
複数の着弾を見せるために機体倍率を自動で下げない。画面外の着弾はミニマップのpulseと方向マーカーで伝える。
演出のカメラshakeはワールド描画にのみ加算し、HUD・入力座標・物理判定を揺らさない。強さ0も設定可能。

## 21.3 入力の所有権

| 入力場所・方式 | 操作 | 条件 |
|---|---|---|
| ワールド上の1指ドラッグ | 地図を指と同じ方向へ動かすパン | 自分／他人の手番どちらでも可 |
| マウスがゲーム表示領域の端へ接触 | 対応方向へカメラ移動 | mouse pointer、フォーカスあり、modalなし |
| ミニマップtap/click | 指定地点へ移動 | 射撃はしない |
| 左操作部の左右ボタン | 機体移動 | 自分の操作可能時間のみ |
| 角度ボタン・角度用ドラッグ領域 | 照準調整 | ワールドのスワイプと分離 |
| 発射ボタン長押し・離す | power蓄積・発射 | pointer captureされた1本のpointerのみ |
| キーボード | A/D移動、上下キー角度、Space発射、Cで注視点復帰 | 文字入力・modal中は無効 |
| キーボードによる見回し | Shift+矢印でパン | 移動・角度入力より優先、同時に実行しない |

端判定はwindow全体ではなく、HUDを除くゲーム表示領域の内側24 CSS px。
領域へ入って120ms後に動き始め、深さに応じて最大480 CSS px/秒。角はベクトルを正規化し斜めだけ速くしない。
pointerleave、blur、visibility hidden、modal表示で即停止。cursorがHUD上なら停止する。
coarse pointerでは端スクロールを使わない。ペンはドラッグパンを基本にする。

パン開始の閾値は8 CSS px。初期版は慣性・pinch zoomなし。touch-action:noneは対戦の操作領域に限定する。
メニューや部屋のリストは通常スクロールを維持する。画面端のOSジェスチャーに必須操作を置かない。
入力開始時にWorldPan / Aim / Move / Fire / UIの所有者を固定し、終了まで乗り換えない。
2本目の指は新しいゲーム操作を始めない。fire中にパンを混ぜず、発射入力の誤確定を避ける。
pointercancel、blur、端末回転、modalを開く操作はpowerを取消。解除を発射として処理しない。
power上限時の自動発射は現行方針を継承し、取消と重なった場合は未確定なら取消を優先する。

## 21.4 対戦HUD

```text
┌─────────────────────────────────────────────────────────────┐
│ 手番 A2 / 次 B1,C1    風の小窓    残り20秒    接続 / 設定     │
├─────────────────────────────────────────────────────────────┤
│ チーム残存数                         画面外の機体 → B2      │
│                                                             │
│                    ワールド表示領域                         │
│            固定感のある機体・弾・地形・名前                   │
│                                           ミニマップ        │
├─────────────────────────────────────────────────────────────┤
│ 移動 ← → / 残量   角度 − 45° ＋   武器   power ━━━  発射     │
└─────────────────────────────────────────────────────────────┘
```

上帯は手番、次の3人、風、時間。下帯は移動、角度、武器、power、発射。
HPはワールドの機体上に表示し、8人全員の詳細カードを常設して戦場を狭めない。
チーム一覧パネルを開くと、全員のHP・接続・脱落・手番順を一覧できる。
敵の未確定角度とpowerは表示しない。風の数値・弾道予測線も既存方針に従い追加しない。
画面外マーカーは方向とTeamId+機体番号を示し、同方向では集約する。押すと視点だけ移す。

下帯は標準88px、狭い画面72px、上帯は標準56px、狭い画面44pxを試作値とする。
すべての必須操作のhit areaは44px以上。幅不足時は武器詳細をsheetへ移し、発射と角度を隠さない。
狭い画面ではミニマップを小さくし、詳細は押して開く。HUD背後はカメラの有効viewportから除外する。
他人の手番では操作盤をコンパクトな「B1の番／次はあなた」に変え、角度などの前回値は保持する。

設定・武器詳細・一覧は一度に1つの補助pane。開いたpaneと閉じたpaneのフォーカス復帰先を記録する。
武器変更は自分の手番のみ確定可能。他人の手番では性能を読むだけにする。
設定paneを開いてもオンライン対戦は止まらない。「対戦は進行中」と残り時間を見える位置へ残す。
次の手番になったら武器paneは選択状態を維持し、設定paneは閉じず通知する。勝手な確定操作はしない。
脱落後は「観戦中」と明記し、発射ボタンを残さない。退出・味方追従・部屋に残る選択を提供する。

## 21.5 メニューとアート

16章の真横の丸いタンク、シアンのガラス、クリーム・サフラン・テラコッタを使う。
キャラクターは19章の一体スプライト。本人専用の黄色いカエル一式は一般ユーザーのdefaultにしない。
背景・タンクはpixel art、文章は読みやすい通常書体。ピクセル装飾を入力欄や長文へ強制しない。

| 画面 | 構成と主要行動 |
|---|---|
| 開始ページ | 大きいマシン、タイトル、はじめる、言語、音、控えめな設定 |
| ガレージ | 左に搭乗マシン、右にプロフィール・外見・武器。下部に対戦と練習 |
| ロビー | すぐ対戦、部屋作成、コード入力。人数・編成・回線目安で部屋を選ぶ |
| 部屋 | A〜Hのチーム欄に機体カードを並べる。未配置、ready、マップとルール |
| リザルト | 勝利チーム、全員のキャラクター反応、与ダメージ、再戦・退出 |

モバイルのメニューは縦持ち対応。primary actionはスクロール領域の外へ置く。
8チームでは1列、PCは複数列。ドラッグでのチーム移動に加え「チームを選ぶ」操作を必ず設ける。
表示名は省略してもプロフィールで全文を確認できる。翻訳で文が伸びてもカード高とボタンが破綻しない。

## 21.6 開始ページの演出案

短い「整備完了から出撃へ」の一連の動きで、所有感と砲撃の予感を作る。

| 時間 | 絵と音 | 操作 |
|---|---|---|
| 0〜0.8秒 | 深い青の背景、ガレージの灯りがつく | スキップを最初から表示 |
| 0.8〜2.0秒 | 履帯が少し動き、マシンが定位置へ。操縦者が顔を上げる | はじめるを先に操作可能にする |
| 2.0〜3.0秒 | 砲身が小さく上がり、ロゴが現れる | タイトルへ移行 |
| タイトルidle | 呼吸、瞬き、ガラスの反射、遠景の雲、控えめな旗 | 常に入力可能 |
| はじめる | マシンが走り出し、ガレージ扉でwipe | ガレージを表示 |

イントロは初回だけ標準再生し、設定から再生可能。再訪は直接idleタイトル。
音は最初のユーザー操作後に有効化し、以前のmuteを尊重する。音が鳴らないことを開始失敗にしない。
タイトルの背景動画は任意の装飾。基本案は既存素材を使ったリアルタイム2D animationとする。
AI動画は6〜8秒の背景loop候補に限定し、文字・CTA・本人の機体を焼き込まない。
世界観の一致、先頭末尾の接続、圧縮品質、配信容量、利用条件を確認してから採用する。
動画が再生できない・省データ・reduced motionなら静止posterへ切り替え、ゲームへ進む機能は維持する。
今回の設計では動画を生成しておらず、採用も未確定。

## 21.7 すべてのシーン遷移

SceneCoordinatorがscene、遷移ID、遷移先、loading状態、取消を管理する。巨大な汎用scene engineは作らない。
ゲーム進行はCoordinatorの外にあり、UI animation完了でサーバーのstateを進めない。

| 遷移 | 演出 | 目安 |
|---|---|---|
| Boot→Intro→Title | 灯りとロゴの連続演出 | 初回合計3秒以内、スキップ可 |
| Title→Garage | 扉のwipe | 350〜500ms |
| Garage↔Lobby、Practiceから戻る | 同方向の短いslide/fade | 180〜250ms |
| Lobby→Room、Room→Lobby | 選んだカードを起点に切替 | 180〜250ms |
| Room→Loading→Battle | ハッチが閉じ、戦場を開く | 導入600〜900ms、読込待ちは別表示 |
| Battle→Result | 最終着弾を見せ、結果帯と搭乗者 | replay後600ms以内 |
| Result→Room/Garage | 結果帯を畳む | 200〜300ms |
| 通信復帰・深いリンク | 短いfade | 0〜150ms |
| 対戦エラーから退避 | 理由を先に表示してfade | 150ms以下 |

共通手順はprepare（必要素材を読む）→cover→scene切替→reveal→focus。
遅い読込はcoverで真っ黒のまま待たせず、進捗・再試行・退出を表示する。失敗時は元画面か安全な退避画面へ戻す。
二重clickは同じ遷移IDへまとめ、古い読込完了は現在のsceneを上書きしない。
表示遷移を取り消しても、確定済みの入室・退出は戻せない。サーバーの現在状態を再取得して整合させる。
scene切替時にイベント・ticker・audioを解放し、対戦session接続だけを画面の外で保持する。
ブラウザbackもCoordinatorを通し、対戦退出だけは降参の意味を明示する。
reduced motionは全経路で150ms以下のfadeか即時切替。flashと大きなズームを避ける。

## 21.8 検証

- camera: screen/world往復、上下左右clamp、viewportより小さいmap、DPR1/2/3、HUD領域、回転。
- input: 端の滞在と離脱、pointercancel、2本指、Space長押し中のblur、pane内スクロール、誤発射ゼロ。
- replay: 複数弾・地下の貫通・高い弾道・全弾画面外・同時撃破でも視点と結果が理解できる。
- scenes: 通常経路と戻る経路、招待、満員、開始済み、二重click、読込失敗、復帰、音声拒否、reduced motion。
- 実機目視: 最小横画面で機体内の顔と砲口を判別し、44px操作を維持。スクリーンショットだけで操作合格にしない。
