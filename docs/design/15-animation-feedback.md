## 次回の生成依頼に含める内容

- 真横、同じキャラクターの体格と画素密度、同じ座席基準。画像のセルを埋めるために各ポーズを拡大しない。
- 全身の自然な目、頭、首、座席位置を識別できる素体。メガネ・スカーフ・キャノピー・武器を素体へ焼き込まない。
- 同一サイズの等間隔セル。ポーズ番号と時間は画像外の manifest に記録する。
- LOW HP は不安、DESTROY は驚き→頭をかばう→様子見、WRECK は落胆。腹の模様で表情を作らない。
- 爆発は小さな発光→膨張→減衰。煙は膨張して薄れる。各コマの大きさの差を保持する。
- 本体形状、接地点、砲身の回転原点、砲口距離を固定する。別種を追加してもカエルを引き伸ばして流用しない。
- 生成結果の alpha、セル間隔、解剖学は必ず確認する。プロンプトへの記載だけで適合済みとしない。

## 書き出し記録

画像生成から書き出す pack は `productionMethod: "imagegen"` を宣言する。
各 asset の `exportMetrics` に使用コマ数分の記録を付ける。
各記録は sourceSheet、sourceFrame、sourceOrigin、sourceSize、outputOrigin、outputSize、scale、group を持つ。
座標は [x,y]、寸法は [width,height] とする。
出力寸法は `max(1, round(sourceSize * scale))`、同じ連続素材は共通 scale とする。
pilot は全使用コマに frameAnchors と frameFaceAreas [x,y,width,height] を持つ。
frameFaceAreas は元資料と目視照合した自然な目の位置で、腹の白い領域を使わない。
生成 pack の記録欠落、縦横別倍率、コマ別倍率、接続点欠落を validate とガレージの両方で拒否する。
手描き pack の exportMetrics は任意だが、付与する場合は同じ検査を受ける。

## 確認手順

1. `pnpm assets:test` と `pnpm assets:validate assets/workbench/baseline-v2` を実行する。
2. ガレージで全アニメーションを検査し、失敗を解消する。
3. 各状態のコマボタンで境界へ移動し、素体・装備付き・左右・仰角両端・低HPを確認する。
4. `pnpm assets:test:browser` を実行し、検査 JSON と PC/モバイル画像を更新する。
5. 新しい問題は、この表へ再現条件・修正・検査を一組として追加する。

この検査は現在の素材とガレージ内の演出が対象である。
対戦の物理、未制作の別種・足回り、武器固有の地形処理との同期まで検証済みとはしない。
自動レポートの humanReview は pending を維持し、目視承認を捏造しない。

## ユーザーからの追加フィードバック

以下は 2026-09-09 のユーザー指摘を保持した制作条件である。

| 指摘 | 次の制作・検査条件 |
|---|---|
| 履帯と機体のサイズが合わない | 履帯は車体幅を支える幅にする。高さだけを伸縮せず、接地位置を共通にする |
| キャラが機体より前に見える | 搭乗者→車体前面→ガラス→枠の順で合成。腰より下は車体が隠す |
| モーション変更後にループしない | 検証用 repeat をゲームの clip.loop と分離。大破→残骸まで再生後に繰り返せる。停止確認も選べる |
| キャラを小さく、砲台を主張する | 搭乗者と砲身の比率を合成状態で確認。素体だけでサイズを決めない |
| 前の光沢がよい、アルファを活用したい | 半透明ガラスを許可する規約へ更新。固定の枠と独立して重ねる |
| キャラ左の不要な線 | 元 sheet の隣のパーツの混入と、座席・車体前面の分離を確認する |
| 爆風が変 | 不等間隔の元 sheet を等間隔と仮定しない。切り出しに隣の爆風・煙・破片が入らないこと、中心が移動しないことを確認する |
| GPT Image 2.5 を使う | 新規生成・編集は gpt-image-2.5-sunburst を明示指定。使用モデルを確認できない経路で代替しない |
| キャラデザから全部やり直す | 搭乗者だけでなく、タンク本体、足回り、武器、砲弾、VFX、モーション全体を新しい一式として制作する |
| 既存画像を使わず初期案から。ただしカエルだけ元の3Dモデルを参照 | カエルの写真は形状・配色・装備の参照として使用。タンク・武器・砲弾・演出には旧生成画像を入力しない。新規配色と造形を検討する |

baseline-v1 は比較と検査ツールの回帰確認用に残す。新規制作を完成扱いにしない。
API キーは .env.imagegen.local に置き、Git・ブラウザ・検査レポートへ出力しない。

## 新しい初期案での確認事項

[original-v1](../../assets/concepts/original-v1/README.md) が最新のデザインボード一式。
カエルの三面図でも装備が混入すること、砲口が斜め投影へ戻ることが GPT Image 2.5 の初回出力で発生した。
高精度モデルでも、素体の全方向と砲口の側面投影を目視する工程を省かない。

変更後に [比較画像とレポート](../../assets/previews/asset-lab-v2/) を再取得する。40項目・368描画、全仰角、16ポーズ、8武器、32VFXコマを再比較し、新たな修正可能な混入・接触・遮蔽の矛盾が出ないことを今回の到達点にする。絵の魅力を数学的に最大化したという意味ではない。

ソースの切り出し領域を変えたら sourceRegion/sourceHash を更新する。枠とガラスのマスク処理はalphaMaskFrameで追跡する。生成モデルや寸法、入力、禁止物を省略した再生成をしない。最初から全画像を生成し直すより、発見した不具合に絞った再生成と同条件の比較を優先する。

PNG/ORA/manifestの再出力を2回実行し、パック全体のSHA-256一致を確認した。ORA内の時刻とZIP拡張属性を固定し、未変更の素材が出力のたびに別物にならないようにした。

レーザー・浮遊砲はシアンのenergy素材を発射部に使い、通常火薬のオレンジ色フラッシュを流用しない。武器別の発射0/30/70/120msを `fire.png` で比較する。


## 塗装範囲のフィードバック（2026-09-09）

- 黄色の点が残る原因はアンチエイリアスではなく、ハイライト・影が固定色のpalette indexへ量子化されたこと。主要3色だけでなく黄色の全階調をprimaryへ登録した。
- 車体・砲身・枠のベージュ/クリームも車体カラーへ連動する。金属、キャラクター、ガラスは独立した固定色を維持する。
- 黒で陰影が消えないようpaletteTonesによる白/黒補間を使う。半透明反射を同じRGBの塗装用ハイライトと誤って一括置換しない。
- 固定色への誤登録を拒否する負例テスト、黒/マゼンタ/青で残色がなくパネルが変わる実画素テスト、反射の不変性を追加。比較画像は paint-black.png / paint-pink.png / paint-blue.png。

### 単発系の弾が砲身に対して小さい（2026-09-09）
- 原因：単発系にも9〜17 artpxの小さな横幅を指定していた。
- 修正：cannon 24×11、drill 24×13、laser 32×9、digger 22×15、floater 18×17、stinger 32×7 artpx。元画像の縦横比を維持して再出力する。
- triple 9×4、multiple 6×6 artpxは承認済みのため維持する。
- 再発防止：`scripts/assets/projectile-size.test.mjs`で単発弾の幅が武器全長の30〜60%、高さ7 artpx以上であること、縦横比と連射弾サイズを検証する。新武器では砲口との見た目も確認して範囲を決定する。
- `pnpm assets:capture`のfire.pngで全8武器の0/30/70/120msを比較する。これは表示寸法の変更で、ゲームの当たり判定や威力には影響しない。

### 採掘弾・レーザーの形状と小さすぎる機体VFX（2026-09-09）
採掘弾を黒い球形爆弾、レーザーを外殻のない白／シアンの光弾に再生成した。元画像のカプセルや掘削ヘッドはこの2種の制作基準として使わない。画像内の論理グリッドではなく実画素を確認し、爆弾は導火線を含むため上650px、レーザーは下374pxを切り出す。

大破・着地・低HPの弱さは、スプライトの縮小率と発生源が1つだけだったことが原因。元画像から拡大再出力し、時間差のある3連爆発、3か所の土煙、3〜4本の上昇煙を組み合わせる。画面端の切れを確認して発生位置を内側に調整した。量を増やすだけでなく、大破600ms・着地450msの終端で透明になり、残骸への遷移で爆発を再発生させないことも検査する。

### 採掘弾の着弾演出を通常爆発に統一（2026-09-09）
黒い爆弾への変更に合わせ、採掘弾の着弾時は標準砲と同じ通常爆発に変更した。専用の掘削エフェクトへの割り当てを解除し、Browser testで標準砲との着弾画素一致を検査する。

### 残骸の撃破済み表示（2026-09-09）
倒されたことを明示するため、残骸状態の機体・キャラクター・煙をグレースケールにした。背景と保存された塗装色は維持し、大破から残骸への遷移時に適用する。

### 残骸の沈み込みと砲身の垂れ下がり（2026-09-09）
残骸の車体を8 artpx沈めて履帯上部に重ね、砲身を18度下向きにした。キャノピー・搭乗者・装備・砲台支点・損傷煙をまとめて追従させる。Unit testで沈み込みと接地維持、Browser testで元の照準角によらず同じ下向き姿勢になることを検証する。

### 発射時に車体も反動で動かす（2026-09-09）
砲身だけが動いていたため、接地した履帯に対して車体全体が最大2 artpx後退して復帰する反動を追加した。キャノピー・搭乗者・装備も共通の変換で追従する。単発だけでなくトリプル・マルチの連射時刻に同期し、発射が終わればずれを残さないことをUnit testで検査する。

### 発射時の搭乗者ののけぞりを解除（2026-09-09）
車体の反動で十分に発射感が出るため、搭乗者のfire clipを通常着座ポーズに変更した。搭乗位置と装備を保持し、車体と一緒に後退する。

### 色変更で目立つ1ドットの散らばり（2026-09-09）
元画像の微細な塗装テクスチャが減色後に斑点として残っていた。塗装内部の孤立点を整理し、車体の大きな平面は明るい階調を統一した。輪郭、金属、アクセント、ガラス、搭乗者を保護する条件を付け、再書き出しでも同じcleanupを行う。
