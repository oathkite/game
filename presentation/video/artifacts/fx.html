動きに状態を運ばせる

キャラクター、エフェクト、ローディング、ページ切り替えの 4 領域で、今の緑と黒のドット表現を崩さずに手触りを厚くする案をまとめた。各案は「その動きで何が読めるようになるか」を先に書き、PixiJS と CSS のどこに置くか、時間の予算、動きを減らす設定での扱いまで添えている。デモはブラウザ上の近似で、実装の寸法や色とは一致しない。

基準 main 91b772d 作成 2026-09-23 対象 apps/client/src/game, worldUi 案 主要 12 + 候補 8

先に決めること：36 章との関係

設計書 36-simple-dot-theme.md（2026-09-13）は、画像によるグラフィック更新を取り下げたときに次のように定めている。

装飾目的の動画・アニメーション制作は終了する。落下、弾の飛翔、着弾、手番のカメラ移動など、状態の把握に必要な動きは維持する。

「よりリッチに」はこの方針と一部で衝突する。そこで各案に 36 章との関係を付けた。範囲内の案はそのまま進められる。改訂が必要な案を採るなら、36 章に理由を書き、99-open-questions.md の TBD を更新してから実装する（CLAUDE.md の「設計書が正」）。

範囲内 状態の把握に必要な動き 境界 情報はあるが装飾寄り。解釈を決める 改訂が必要 主に雰囲気のための動き 要判断 ゲーム性に影響する

すべての案で守ること

既存の hitFeedback.ts と turnCaret.ts の作り方に合わせる。

sim を触らない演出は client だけに置く。当たり判定と地形 mask は変えず、e2e の mismatches 0 を保つ。
時間は純関数、乱数なしblastFrameAt(t, …) の形で「経過時間 → 見え方」を返す関数にして単体テストする。ばらつきは DEBRIS_VELOCITIES のような固定表か、着弾座標から決める。
ターンを延ばさない着弾は練習で 590 ms（IMPACT_TOTAL_MS）、オンラインではサーバーが決めた再生時間（labReplay.ts の endsAt）の中。画面切り替えは 400 ms。新しい演出はこの中に重ねるか、進行を待たせない。
ドット単位で動かす位置は整数セルか art px に丸める。CSS は steps() を使い、なめらかな補間で輪郭をぼかさない。HUD 層のドットは 2 px。
動きを減らす設定に従うprefers-reduced-motion では止めるか、最後の姿だけを出す。キャレット、揺れ、シャッターと同じ扱い。
画像素材を使わない36 章に従い Graphics.rect と CSS だけで描く。関数は 50 行未満に分ける。

オンライン対戦に練習の着弾演出を揃える

範囲内

オンライン対戦の爆風は labReplay.ts が 300 ms だけ出す単色の円で、白フラッシュは一律 150 ms。練習の replay.ts が使う hitFeedback.ts の広がり、明滅、輪、破片、画面揺れ、HP バーの減少と明滅は届いていない。主に遊ばれる側の手応えが薄い。テスト済みの時間関数をオンラインでも呼び、着弾ごとの経過時間から同じ見え方を出す。新しい表現を作らずに済み、以後のエフェクト案（E2、E4、C5）も 1 か所に入れるだけで両方へ届く。

試す順番のおすすめ

36 章の範囲内で、効果が大きく、戻しやすいものから並べた。

  1. E1 オンライン対戦に練習の着弾演出を揃える

    新しい表現を作らず、テスト済みの関数を主なモードへ届けるだけで手応えが大きく変わる。以後のエフェクト案の土台になる。

  2. L1 端末ログ風の待ち表示

    今いちばん弱い画面で、ゲームの進行に一切触れない。1 PR で完結する。

  3. E2 地形の縁が崩れる

    毎ターン必ず見る着弾の手応えが増える。時間の純関数と単体テストで固めやすい。

  4. C1 手番の振動 と C4 HP が少ない機体の煙

    どちらも tankView.ts の同じ場所に入る。8 人対戦での読みやすさに直結する。

  5. P2 リザルトの段階表示

    CSS だけで済み、境界の案の中で危険が最も小さい。36 章の解釈を決める試金石になる。
